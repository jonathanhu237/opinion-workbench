# 修复自动任务无法删除

## Goal

让用户能够从“自动任务”页面移除不再需要的任务，并确保被移除的任务不会再被计划调度，同时不破坏自动工作流的历史证据和运行安全性。

## Background

- 当前自动任务 API 只有列表、创建、读取、全量更新、立即运行和运行控制，没有删除端点（`backend/src/longtian_api/api/v1/automation_workflows.py:90`）。
- 当前任务卡只有立即运行、查看运行、编辑和启停操作，没有删除入口（`frontend/src/routes/automation-tasks.tsx:266`）。
- 自动任务被计划、运行、阶段尝试、内容归属和幂等请求等多张表以 `ON DELETE RESTRICT` 引用；运行还保存不可变任务快照，因此直接物理删除任务会破坏现有历史模型（`backend/src/longtian_api/migrations/automation_workflows.py:50`、`:56`、`:81`、`:103`、`:128`、`:136`、`:143`）。
- 任务列表、调度器和工作台当前都会直接读取 `automation_tasks`；删除语义必须在这些读取边界保持一致（`backend/src/longtian_api/repositories/automation_workflows.py:318`、`:391`、`backend/src/longtian_api/repositories/workbench.py:91`、`:443`）。
- 既有自动工作流约定要求运行快照和阶段历史可追溯；取消运行也不删除已完成的采集或分析结果。

## Requirements

- **R1 — User-visible delete action.** 自动任务列表为每个可删除任务提供明确的“删除”操作，使用危险操作样式和二次确认，确认文案说明未来调度与历史记录的处理方式。
- **R2 — Durable removal.** 删除成功后，该任务立即从普通任务列表消失，刷新页面或重启应用后仍不再出现。
- **R3 — Scheduling fence.** 删除与停用未来调度在同一数据库事务完成；删除成功后不得再认领该任务的新计划触发。
- **R4 — Concurrency safety.** 删除请求使用任务修订号防止陈旧页面误删已被更新的任务；未知任务、修订冲突和运行中任务返回稳定产品错误，不泄露 SQLite 细节。
- **R5 — Cross-layer consistency.** API 客户端、TanStack Query 缓存、分页、任务详情、工作台提醒和“下一次自动任务”均不得继续把已删除任务当作可操作任务。
- **R6 — Existing mutation protections.** 删除端点继续使用本机 Host/Origin/JSON 等现有写操作保护以及 `Cache-Control: no-store`。
- **R7 — Accessible feedback.** 用户取消确认时不产生写入；删除中不可重复提交；成功与失败均有可读状态反馈，成功后焦点回到稳定的任务列表控件。
- **R8 — Preserve history.** 删除只移除可编辑任务配置与未来调度；既有运行、阶段结果、采集/分析产物和报告继续保留并可通过原有运行或报告入口读取。删除不会隐式取消活动运行，用户必须先取消并等待其结束。
- **R9 — Name reuse and replay.** 删除后允许创建同名新任务；完全相同删除请求在响应丢失后重试不得恢复任务或损坏历史。

## Acceptance Criteria

- [x] **AC1 (R1, R7)** 用户可从自动任务卡发起删除；二次确认可取消，取消后任务保持不变。
- [x] **AC2 (R2, R3)** 确认删除后任务从列表消失，重载/重启后仍隐藏，且调度 tick 不会再为它创建 occurrence 或 run。
- [x] **AC3 (R4)** 陈旧修订、未知任务和存在活动运行分别得到确定的 409/404 产品错误；活动运行不会被删除操作隐式取消。
- [x] **AC4 (R5)** 删除成功会失效任务列表、任务详情和工作台查询；分页不会重复或跳过仍存在的任务。
- [x] **AC5 (R5, R8)** 已删除任务不出现在工作台任务提醒或下一次计划中；既有运行和报告仍可由其独立详情入口读取且内容不变。
- [x] **AC6 (R6)** HTTP/OpenAPI、仓储/服务、迁移、前端解码与交互测试覆盖删除契约，后端与前端完整质量门禁通过。
- [x] **AC7 (R9)** 删除后可创建同名新任务；相同修订号的删除请求重试为幂等成功，不产生额外数据变更。

## Out of Scope

- 批量删除、回收站、恢复已删除任务和自动清理历史数据。
- 删除监控规则、采集结果、初步分析或报告本身。
- 改变自动任务的固定三阶段工作流、启停、取消或重试语义。

## Key Decisions

- 采用不可恢复的软删除：普通任务入口隐藏该任务并停止未来调度，但保留不可变运行和报告历史。
- 有活动运行时拒绝删除，用户先使用现有取消操作；删除不会替用户取消或等待后台工作。
- 不提供回收站或恢复入口；删除后允许使用原名称新建一个具有新 ID 的任务。
