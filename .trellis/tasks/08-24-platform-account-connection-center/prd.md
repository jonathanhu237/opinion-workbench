# 平台账号连接中心 MVP

## Goal

为本机单用户提供一个“平台账号连接中心”，让用户在网页中看到目标平台的当前
连接状态，并能发起一次只检测登录态、必要时打开真实 Chrome 由用户人工登录的
流程。该流程不得触发搜索、详情、评论或媒体采集。

## Confirmed Product Decisions

- 应用本身不设置账号登录；谁在本机运行，谁使用。
- 前端使用 React，后端使用 FastAPI；页面沿用现有 shadcn `base-nova`、Tailwind
  与龙田街道本机工作台视觉体系。
- MVP 优先复用用户当前 Chrome Profile。Chrome 未运行时可由程序启动；用户按
  Chrome 的安全机制批准远程调试连接。
- 不在前端表单中收集平台账号、密码、短信验证码或 Cookie。
- 登录态由浏览器持有；Cookie、LocalStorage、二维码内容和认证请求头不得写入
  前端、API JSON、SQLite 或日志。
- 平台在线探针是登录状态的权威依据，不能仅根据 Cookie 文件或 Cookie 名称判断。
- 滑块、验证码及平台安全验证只允许用户在可见浏览器中人工完成，不自动绕过。
- API 及浏览器调试端口只监听 loopback。

## Current Technical Evidence

- MediaCrawler 派生仓库中，微博、抖音、快手和小红书已接入
  `CDPBrowserManager`，可以走“连接现有 Chrome”的路径，并各自具有在线登录
  探针。
- 微博、快手和小红书已验证独立浏览器下的显式认证状态保存/恢复；抖音已验证
  原生持久 Profile 的二次启动复用。上述能力不等同于产品已具备统一连接中心。
- 现有 `auth_validation` 仅是历史验证脚本直接写入配置的内部模式，不是正式 CLI
  类型，不能直接作为稳定的 FastAPI 调用契约。
- 今日头条当前明确忽略 CDP，启动独立可见浏览器，并在认证后直接进入搜索；要接入
  统一中心，必须新增“只检测/只登录”路径并适配现有 Chrome。
- 现有 FastAPI 只有健康检查，React 只有初始化首页；项目尚未引入 SQLite 业务层。

## MVP Scope

- 产品使用带固定导航与紧凑顶栏的后台应用壳；工作台与平台账号是首批真实路由，
  其余业务模块只在导航中如实标注“规划中”，不得展示虚构数据或可点击的伪页面。
- “平台账号”页面展示微博、抖音、快手、小红书、今日头条五个平台条目，统一表达：
  `待检测`、`检测中`、`已连接`、`未连接`、`需要人工操作`、`检测失败`、`暂未接入`。
- 本任务只让微博完成真实闭环：检测 → 必要时打开/连接 Chrome → 用户人工扫码或
  验证 → 在线复检 → 页面显示结果。
- 抖音、快手、小红书、今日头条在页面中保留明确的“待接入”状态，不提供伪按钮；
  后续按平台分别接入并做真实回归。
- 首版状态仅代表当前后端会话中的最近一次在线检测，不为此单独引入 SQLite。

## Requirements

### Administration shell and connection overview

- 首页是紧凑的工作台概览，用真实的本机服务与平台连接数据表达系统准备情况；
  平台连接功能迁入独立的“平台账号”路由，不保留独立的系统登录页。
- 桌面端提供清晰的左侧主导航，移动端提供可键盘操作、可关闭的导航抽屉；当前路由
  必须具有可辨识的选中状态和页面标题。
- 导航预留工作台、平台账号、采集任务、舆情信息、监控关键词、舆情日报和系统设置；
  未实现模块必须禁用并标注“规划中”。
- 页面组合优先使用仓库内已审查的 shadcn `base-nova` 组件；复杂交互不得重新手写
  已由 Base UI/shadcn 提供的焦点、抽屉或提示行为。
- 页面能区分平台尚未检查、正在检查、已登录、未登录、需要用户操作、失败和暂未
  支持，且不能把“浏览器中存在状态文件”误报为“已连接”。
- 每个平台显示最近一次检测结果和可执行的下一步；后端重启后允许回到“待检测”。
- 页面应保留本机后端连通性提示，但不让健康检查抢占平台连接中心的主要层级。

### Weibo connection flow

- 用户可以发起微博连接；请求快速返回，由后台运行有界的交互任务，前端轮询任务
  状态，不能让一个 HTTP 请求一直等待扫码完成。
- 同一时刻只允许一个浏览器认证任务，重复点击不得并发启动多个 Chrome/CDP 会话。
- 任务只运行认证验证模式，不得调用任何内容搜索、详情、作者、评论或媒体采集入口。
- 已登录时，在线探针通过后直接返回“已连接”。
- 未登录时，程序连接或启动真实 Chrome，打开微博官方页面，由用户人工完成扫码或
  官方验证，再次运行在线探针。
- 用户未授权 Chrome、登录超时、浏览器被关闭或探针失败时，返回可操作但不泄露
  底层凭据/页面内容的错误信息，并允许重试。
- 完成或失败后释放任务拥有的页面、进程句柄和 CDP 资源；不得关闭用户原本打开的
  Chrome。

### API and frontend contract

- FastAPI 使用明确的 Pydantic 响应模型过滤输出，API 不暴露原始子进程输出、
  Cookie、二维码正文、认证 header 或完整异常堆栈。
- 平台列表属于 TanStack Query 管理的服务端状态；开始连接属于 mutation，并按任务
  状态刷新对应平台。
- 前端对外部 JSON 保持运行时校验，支持请求取消、重复操作禁用、键盘操作、可见
  焦点和状态 live region。
- 平台品牌标识仅使用已审查的文字/资产；不得用 Lucide 通用图标冒充平台 Logo。

## Non-Goals

- 本任务不实现关键词、采集任务、舆情列表、AI 分类、日报或通知。
- 不自动处理滑块、CAPTCHA、短信或其他平台安全挑战。
- 不把用户完整 Chrome Profile、浏览器数据目录或认证凭据复制进项目数据库。
- 不承诺 Chrome/后端重启后的完全无人值守；默认 Profile 的远程调试可能再次要求
  用户批准。
- 不实现抖音、快手、小红书和今日头条的真实检测或登录编排。

## Acceptance Criteria

- [x] 产品呈现为可响应、可键盘操作的后台控制台，工作台和平台账号具有独立路由，
  当前导航清楚，未实现模块明确标注“规划中”。
- [x] 页面主体使用已审查的 shadcn `base-nova` 组件完成应用壳、状态卡片、操作区和
  移动导航，不退回成落地页式大标题布局。
- [x] 平台账号页面展示五个平台及准确、可理解的状态和下一步操作。
- [x] 后端离线、浏览器未授权、登录超时、任务冲突和普通失败均有明确 UI 状态。
- [x] 微博能从页面发起真实检测；已有登录态时不要求重复扫码。
- [x] 微博未登录时能打开/连接可见 Chrome，用户人工登录后在线复检为已连接。
- [x] 微博认证任务全程没有内容采集调用，且有自动化哨兵测试证明。
- [x] 同时重复发起任务不会创建并行浏览器会话。
- [x] API、日志、测试夹具和前端状态中不包含认证秘密或二维码正文。
- [x] 认证任务结束后不关闭用户原本的 Chrome，且只清理自身页面/连接资源。
- [x] React 单元/交互测试、FastAPI API/任务测试、MediaCrawler 定向测试、静态检查
  与生产构建通过。
- [x] 使用 loopback 前后端进行真实 Chrome 回归并记录非敏感结果。
