# 采集失败人工处理与断点续采

## Goal

当采集任务中的某个平台失败时，暂停整批，让用户查看原因、到谷歌浏览器中人工处理，再继续未完成的搜索或主动跳过该平台；保留已采结果，不重复执行已确认完成的词和平台。

## Background and Confirmed Evidence

以下为实施前基线；当前实施与验证结果见 `research/implementation-verification.md`。

- 2026-08-28 用户明确选择“平台失败后暂停整批”，接受无人操作时后续平台等待，并在最终规划总结后回复“ok”，批准按本方案实施。
- 当前只有 `manual_challenge_required` 会使平台项和整批进入人工暂停；其他失败记录为 `failed` 并继续后续平台。来源：`backend/src/longtian_api/repositories/search_batches.py:303`、`backend/src/longtian_api/services/search_batches.py:324`。
- 现有“继续采集”仅接受暂停中的批次，将当前平台重新排队，随后创建新的尝试，并复制该批次的全部搜索词。它保留了历史尝试，但不是搜索词级断点续采。来源：`backend/src/longtian_api/repositories/search_batches.py:210`、`:400`，`backend/src/longtian_api/services/search_runs.py:391`。
- 当前界面只提供验证码/滑块的通用提示、继续采集和取消批次，没有失败原因对应的人工处理入口或跳过当前平台的操作。来源：`frontend/src/routes/collection-batch-detail.tsx:386`。
- 小红书先打开首页，再通过接口逐词搜索，因此接口报告需要验证不代表当前可见页面已展示验证码；人工处理入口不能只依赖通用提示。来源：`third_party/MediaCrawler/media_platform/xhs/product_search.py:559`、`:609`。
- 头条的页面识别失败会归为 `structure_changed`，且正常清理该任务创建的页面；重新登录不保证能修复识别问题。来源：`third_party/MediaCrawler/media_platform/toutiao/product_search.py:93`。
- 现有批次规范要求共用一个谷歌浏览器操作所有权、串行采集、保留不可改写的尝试历史。旧需求曾明确将断点续搜排除在范围外；本任务是新增恢复能力，不把旧行为一概记为实现错误。来源：`.trellis/spec/backend/batch-search-guidelines.md`、`.trellis/tasks/archive/2026-08/08-26-multi-platform-batch-collection/prd.md`。

## Requirements

- R1（保留记录）：保存已入库结果、搜索词进度和每次尝试记录，显示具体平台、失败搜索词及真实失败类别；尚未开始搜索时不得虚构失败搜索词。
- R2（人工入口）：提供“打开平台”。优先回到该任务保留的官方页面；页面已关闭或连接失效时，在用户点击后重新打开官方入口。成功打开仅表示页面已显示，不表示已登录、已验证或恢复成功。没有实际验证入口时如实提示。
- R3（断点续采）：用户点击“继续采集”后，从失败或未确认完成的搜索词重新尝试，再处理剩余搜索词。已确认完成的词（包括零结果的词）不重跑；失败词已有部分结果仍保留并去重。所有词都已确认完成时无需再发平台请求，也不得篡改上次失败记录。
- R4（暂停、跳过、取消）：可持久化的平台失败均暂停整批，用户明确继续或跳过前后续平台不执行。提供“跳过此平台”和“取消批次”；跳过显示独立的已跳过状态，不冒充成功。存储故障无法保存暂停时停止调度并如实报错。
- R5（重启与并发）：刷新、断开浏览器或重启后仍可查看进度。中断的批次恢复为等待人工确认，不自动请求平台。重复点击、旧页面的迟到操作或同时打开多个应用页面不能造成重复尝试、误跳过后续平台或并行控制浏览器。
- R6（真实原因）：登录、安全验证、平台限制、结果识别失败、浏览器异常和内部错误分别说明，不统一提示重新登录。再次失败仍暂停并保留本次原因，不能承诺人工处理能解决所有错误。
- R7（浏览器边界）：人工处理与自动采集不得争抢共用浏览器；只操作本任务创建的页面，不关闭用户原有标签页，不读取密码、不代做安全验证、不绕过平台访问限制。
- R8（界面）：复用现有批次详情、平台进度和结果样式，使用 Shadcn UI 组件及既有配色。操作按钮和反馈简洁明确、支持键盘；不新增侧边栏模块、假状态或冗余指引。
- R9（已有失败任务）：已结束且包含失败的批次，允许用户选择其中一个失败平台，点击“处理此平台”后重新进入暂停处理流程；不自动采集、不连带重跑成功平台。已有其他执行/暂停任务时拒绝抢占。保留旧批次结束时间和尝试历史；取消/全成功批次不因此重新开启。
- R10（合并结果）：平台结果和新增/再次命中数量按所有尝试去重汇总，旧尝试仍可单独查看。不能因继续采集而隐藏先前结果，也不能把同一内容的再次命中累加为多个新增结果。
- R11（旧数据兼容）：已有暂停记录按可证明的旧进度恢复，当前/最后一个未确认完成的词仍需重试；不伪造旧记录的逐词完成时间。进度证据不一致时明确提示无法可靠续采，保留跳过/取消，不悄悄从头重跑。旧单平台历史链接继续可读。

## Acceptance Criteria

2026-08-28：AC1–AC11 的自动化/隔离模拟验证已通过，详见
`research/implementation-verification.md` 和 `research/final-check.md`。下列签收框暂保留，
不将模拟测试等同于真实平台验收。随后经用户批准，正式库升级及批次 8 的小红书
断点续采已通过：仅续采最后 4 词，结果从 108 条去重增加至 126 条，原记录和成功平台
保持。见 `research/live-upgrade-verification.md`。本次没有出现真实验证码，不能据此
声称已实测验证码处理后的恢复；下列签收框仍待最终验收确认。

- [ ] AC1（R1、R6）：登录、验证、连接异常、结果识别失败分别呈现准确原因，不统一显示“请登录”；搜索开始前失败不显示虚构的失败词。
- [ ] AC2（R2、R7）：打开已有官方页不刷新、不重新搜索；缺少可用页面时只打开一次官方入口。小红书接口要求验证但首页没有验证码时不显示“验证码已打开”，人工处理期间无自动平台操作。
- [ ] AC3（R1、R3）：第 7 个搜索词失败后继续，仅请求第 7 个及后续词；前 6 个含零结果的完成词不重复请求。连续两次恢复仍按最新确认位置推进。
- [ ] AC4（R1、R3、R10）：失败前已采 A/B，继续时返回 B/C，平台合计只有 A/B/C 三条；旧尝试保留，新增/再次命中及匹配词汇总准确。
- [ ] AC5（R4）：跳过后显示“已跳过”并执行下一个平台；取消后后续平台不启动。两种情况都保留已采结果，整批不能错误显示全部成功。
- [ ] AC6（R5、R7）：刷新/重启不发平台请求；旧页面的继续/跳过请求被拒绝并刷新状态，取消与数据库写入或页面打开竞争时无孤立任务、无后续平台误启动。
- [ ] AC7（R8）：四个操作使用现有 Shadcn UI，有清晰的处理中/失败反馈、键盘操作与窄屏布局，颜色和字体不改版。
- [ ] AC8（R4）：普通失败和安全验证均暂停整批，未得到用户继续或跳过指令前后续平台没有请求；服务端、接口和界面状态一致。
- [ ] AC9（R3）：所有词已确认完成但最终连接/清理失败时，继续不新增尝试、不重新请求该平台；界面保留上次失败记录，同时正确结束该平台采集。
- [ ] AC10（R9）：显式处理一个已有失败平台只恢复该项，其余成功项不重跑，旧结束时间留存；其他批次正在执行/暂停时不能抢占，取消/成功批次不能误恢复。
- [ ] AC11（R11）：旧版本记录迁移保留所有 ID、结果、词和关系；可证明的空结果前缀可续采，最后未确认词不会被跳过，异常记录不会伪装成可信断点。

## Out of Scope

- 定时采集、后台自动重试、多个平台并行采集、跨设备同步。
- 搜索词内部的页级断点、全网覆盖承诺、跨进程多后端并行运行。
- 自动填写账号密码、自动完成验证码或绕过风控。
- 保证人工操作能够修复平台拒绝访问、所有 DOM/接口变化或所有结果识别故障。
- 当前头条 `structure_changed` 的独立根因修复、AI 筛选/汇总、采集结果排序。
- 重新开启已取消/全成功批次，以及为旧 standalone 运行另建恢复界面。
- 本轮规划中发起真实采集、修改现有批次状态、付费模型调用、提交或推送代码。

## Technical Notes and Review Status

- `design.md` 记录完成证据、搜索协议、人工页面、结果汇总和兼容设计；`implement.md` 记录实施顺序及验证。研究证据在 `research/`，不以模拟或源代码推断冒充真实平台验收。
- “已完成”指满足当前每词数量/分页上限的搜索，不代表平台上已没有其他内容。未确认词允许重复请求，但已入库结果幂等保留；不承诺平台请求严格只发生一次。
- 官方页面是否实际提供验证码属于外部限制；保留页面及人工入口不能保证验证可达。需要真实验证时由用户完成，没有出现则如实记录。
- 当前需求已收敛，2026-08-28 最终方案已获用户批准，进入实施；真实批次操作、提交和推送仍按各自边界执行。
