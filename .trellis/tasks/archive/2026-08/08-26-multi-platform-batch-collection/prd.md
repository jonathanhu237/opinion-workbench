# 多平台批量采集

## Goal

让用户在“采集任务”页面一次选择一个或多个平台并提交一次，系统按固定顺序完成所选平台的搜索，减少重复选择同一监控规则和采集数量的操作，同时保持每个平台的进度、结果和失败状态可独立查看。

## Background

- 当前五个平台（今日头条、微博、快手、抖音、小红书）都已经具备独立搜索能力。
- 当前表单只接受一个平台；一次提交只创建一个持久化采集任务，并在创建后进入该任务详情页。
- 每个采集任务只属于一个平台，结果按 `(platform, platform_content_id)` 全局去重。
- 平台账号检查、平台搜索和小红书结果打开共用同一套谷歌浏览器操作协调器，任意时刻只能有一个浏览器操作。
- 当前运行记录、进度、取消和结果详情都是单平台任务模型；已有历史数据和深链接必须继续可用。

## Requirements

- “采集平台”改为可访问的多选控件，展示五个平台的现有 Logo 和中文名称，初始默认全选；用户可以取消任意平台，但至少选择一个平台才能开始采集。
- 一次提交复用同一条已启用监控规则和同一个“每词最多采集”数值，为每个选中平台建立独立、可追溯的采集任务。
- 所选平台按产品目录中的固定顺序串行执行，不并发控制谷歌浏览器。
- 每个平台继续拥有独立的运行状态、当前搜索词进度、新增/再次命中数量、结果详情和失败原因；一个平台的结果不得混入另一个平台的任务。
- 提交成功后进入新的批次总览页，展示整批进度和各平台状态、数量及详情入口；原有单平台任务详情页继续作为平台级下钻页面。
- 某个平台出现未登录、访问限制、页面或协议变化、浏览器不可用、超时或内部故障时，记录该平台的真实终态并继续后续平台。
- 某个平台需要用户现场处理验证码、滑块或其他人工安全验证时，暂停整批采集并保留该平台的可见验证页面；用户处理后可以明确继续或取消剩余平台。
- 用户完成人工安全验证并点击“继续采集”后，先为被中断的平台创建一次新的尝试；该平台成功或再次形成真实终态后，再按既定顺序处理后续平台。批次总览默认展示该平台的最新尝试，同时保留旧尝试用于排查。
- 批量进度需要在页面刷新或应用重启后仍可恢复，不得仅依赖当前 React 页面中的临时队列。
- 应用重启时，已中断的执行中尝试按真实故障收敛，尚未开始的平台继续按队列执行；处于人工验证暂停状态的批次保持暂停，不能擅自重试。
- 用户可取消尚未结束的整批采集；正在执行的平台按现有取消协议结束，尚未开始的平台不得再启动，并留下真实、可识别的取消状态。
- 已有单平台运行详情、历史记录、结果打开、跨运行去重和平台账号检测行为保持兼容。
- 所有 API 与错误响应继续使用严格、可验证且不泄露关键词、Cookie、浏览器状态或原始平台响应的产品契约。

## Acceptance Criteria

- [ ] 页面初始默认勾选五个平台；用户可以改为任意 1–5 个平台，未选择平台时无法提交并得到明确中文提示。
- [ ] 一次选择三个平台并提交后，系统只为这三个平台创建任务，并按照固定平台顺序逐个执行，任何时刻最多一个平台处于浏览器执行阶段。
- [ ] 提交后进入批次总览；总览显示每个所选平台的等待/执行/暂停/终态、结果数量和任务详情入口，并能从历史记录重新打开。
- [ ] 刷新页面或重启本机应用后，仍能看到该批采集、所含平台任务及真实进度，并继续或正确收敛未完成状态。
- [ ] 每个平台的状态、结果数量、原文结果和失败原因可独立查看；部分成功不会被汇总成“全部成功”。
- [ ] 普通平台失败不会阻止后续平台；需要人工安全验证时批次暂停，刷新页面后仍显示暂停原因和继续/取消操作。
- [ ] 完成人工验证并继续后，被中断的平台生成新的可审计尝试并优先重试；旧尝试仍可查看，批次总览展示最新尝试的状态和数量。
- [ ] 同一内容在同平台后续任务中继续判定为“历史内容再次命中”，不同平台的相同内容 ID 不会误合并。
- [ ] 取消整批采集后，正在运行的任务结束为已取消，尚未开始的平台不会启动；已完成平台的结果保持不变。
- [ ] 已有单平台历史任务和详情链接无需迁移操作即可继续读取，今日头条、微博、快手、抖音、小红书单独采集均无回归。
- [ ] 前端、FastAPI、SQLite、跨层契约以及真实谷歌浏览器串行验收全部通过。

## Out of Scope

- 多个平台并行控制浏览器。
- 定时执行、自动重试、断点续搜或跨设备同步。
- AI 情绪分析、风险分级、摘要、日报和通知。
- 修改各平台现有搜索协议、登录方式、风控处理或采集范围。
