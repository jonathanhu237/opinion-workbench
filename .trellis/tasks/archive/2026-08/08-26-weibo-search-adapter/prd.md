# 微博搜索适配

## Goal

让用户在现有“采集任务”页面选择微博，使用已保存的监控规则在用户批准的谷歌浏览器会话中执行一次有边界的关键词搜索，并把微博原文以统一的搜索运行和去重结果保存、展示。

## Background

- 现有产品搜索仅接受 `toutiao`，但运行、结果、来源词、新旧判断和取消等业务模型可扩展到其他平台。
- 微博账号检测已经能复用同一个常驻浏览器连接。
- MediaCrawler 现有微博搜索调用 `m.weibo.cn` 内部接口，每个请求最多重试五次，并可能输出原始错误响应；默认通用采集配置还可能继续抓全文、评论或图片。
- 现有微博存储能够提供微博 ID、清理后的正文、原文链接、来源词和发布时间，并对创作者信息做过脱敏；产品搜索只需要更窄的发现结果。
- 能力审计把微博列为今日头条之后风险最低的下一平台，但还没有产品级搜索协议测试或真实关键词搜索验收。

## Requirements

### Search behavior

- 采集任务页面增加微博作为真实可执行平台，而不是占位选项。
- 首版通过一个产品专用、范围受限的适配器复用 MediaCrawler 现有微博搜索接口；不新增微博页面 DOM 解析器。
- 首版固定使用微博“实时”搜索，不增加排序选择控件。
- 用户选择一条已启用监控规则后，微博按规则中的每个词独立搜索，并保留同一内容命中的全部来源词。
- 每次搜索继续遵守现有单次任务的词数上限、每词结果上限、取消和全局浏览器串行约束。
- 微博结果至少包含稳定微博 ID、可读正文或标题、安全原文链接、来源词、平台发布时间以及首次和最近发现时间。
- 产品结果只做内容发现；不采集评论、用户主页、媒体文件，也不为了补全文本额外请求详情。

### Outcomes and safety

- 空结果、需要登录、需要人工安全验证、平台限制或限流、页面或协议变化、浏览器不可用、取消和内部错误必须明确区分。
- 失败前已经规范化并持久化的部分结果可以保留，但运行状态不得伪装成成功。
- 搜索只使用常驻 MediaCrawler worker 和用户批准的谷歌浏览器，不启动备用浏览器，不关闭已有标签页或浏览器上下文。
- 不自动处理短信、滑块、验证码或其他安全验证，不做高频重试。
- 产品适配器不得沿用现有最多五次重试和原始响应日志；请求次数必须有明确上限，平台错误必须转换为受控终态。
- 原始微博响应、Cookie、认证头、LocalStorage、原始 HTML、未脱敏创作者身份和原始异常不得进入产品 API、前端、运行证据或不受控日志。

### Compatibility

- 复用现有搜索运行、SQLite 全局内容、运行观察和来源词关系；微博内容以 `(wb, platform_content_id)` 去重。
- 已有今日头条运行和结果保持可读、可筛选、可取消，不要求迁移或重新采集。
- 平台账号检测、监控规则和现有平台账号页面保持兼容。

## Acceptance Criteria

- [x] 用户可以在采集任务中选择微博并启动一个持久化运行，HTTP 请求不会等待整次浏览器搜索结束。
- [x] 所有规则词均按 OR 语义独立执行，重复微博在单次运行中只出现一次并保留全部命中词。
- [x] 再次搜到已有微博时不新增全局内容行，而是标记为历史内容再次命中、保留首次发现时间并更新最近发现时间。
- [x] 微博原文链接统一为无查询参数和片段的 `https://m.weibo.cn/detail/<微博ID>`，且结果正文不包含未清理的 HTML。
- [x] 微博的空结果、登录、人工验证、限流或限制、协议变化、取消和内部错误不会被错误表示成成功空结果。
- [x] 取消或结束搜索只清理任务自己拥有的资源，用户原有标签页、谷歌浏览器和常驻调试连接仍可继续使用。
- [x] 后端、前端、MediaCrawler、数据库迁移、跨层契约和真实谷歌浏览器验收全部通过，今日头条及账号检测无回归。

## Out of Scope

- 微博评论、转发链、完整用户资料、图片或视频下载、批量博主采集和历史回填。
- 定时调度、自动重试任务、自动登录以及验证码或滑块绕过。
- 快手、抖音和小红书搜索适配。

## Key Decisions

- 2026-08-26：首版收窄复用 MediaCrawler 现有微博搜索接口，不采用可见页面 DOM 解析。代价是需要承担内部接口变化的维护风险；通过禁用全文、评论和媒体采集，限制请求与重试，移除原始响应日志，并输出明确终态来控制产品边界。
- 2026-08-26：首版固定使用微博“实时”排序，优先发现最新舆情，不增加排序设置。接受它相较“综合”排序可能降低相关性排序质量的取舍。
