# 端到端舆情工作流编排与项目收口

## Goal

用统一的自动任务和工作流运行取代当前由定时采集、初步分析完成事件和报告完成事件自行接力的方式。用户配置一个周期性自动任务后，系统按固定链路完成候选内容采集、通用内容理解、任务目标相关性判断和报告生成，并提供完整状态、取消与断点重试。

## Background and Confirmed Facts

- 当前代码已经分别实现定时采集、全量新内容初步分析、文本相关性判断、自动报告和工作台观察，核心实现已在提交 `61f2b15` 中通过隔离验收。
- 当前自动控制分散在 `CollectionScheduleService`、采集完成回调、`ContentAnalysisService.on_job_finished` 和 `TopicReportService.initial_analysis_finished`。它能形成链路，但没有一个拥有整次业务运行的持久化实体。
- 现有采集器、全局内容去重、媒体补全、多模态内容理解、严格模型解码、文本报告树、资源互斥和历史结果均是可复用的领域能力，不需要重写。
- 项目尚未部署，不存在需要兼容的生产自动任务数据。现有本地 `runtime/` 数据库和备份是开发数据，不作为新自动任务的数据迁移验收对象。

## Requirements

### Automatic task definition

- **R1 — One product object.** 新增独立“自动任务”模块。任务至少保存名称、监控规则引用、平台、每个搜索词采集上限、舆情分析目标、计划方式、启用状态和并发修订号。
- **R2 — Fixed pipeline.** 自动链路固定为“采集 → 初步分析 → 相关性判断与报告”。用户不能关闭、跳过、插入、替换或重排阶段；产品不提供通用工作流编辑器。
- **R3 — Task-specific objective.** 每个自动任务有独立、非空的舆情分析目标，用于说明“什么内容对本任务相关”。它与用于扩大候选召回的监控规则/搜索词分离。系统阶段和系统提示模板不向自动任务用户开放编辑。
- **R4 — Scheduling.** 第一版支持两种互斥计划：1–43,200 分钟的固定间隔，以及按 IANA 时区每天一个固定 `HH:MM` 时间。暂不支持每周选择、节假日规则或 Cron 表达式。
- **R5 — Explicit activation.** 新自动任务默认停用。启用、停用或修改计划只影响未来触发，不取消已接受的运行。
- **R6 — Run now.** 用户可以“立即运行一次”。它使用同一固定链路和恢复规则，不改变下一次计划时间；同一任务已有活动运行时明确拒绝，不创建隐藏队列。

### Frozen run and stage semantics

- **R7 — One durable run.** 每个被接受的计划或立即触发创建一个统一工作流运行。运行拥有固定阶段、当前状态、开始/结束时间、失败原因、关联子任务和最终报告。
- **R8 — Frozen intent.** 运行在接受时冻结任务修订、规则名称及有序搜索词、平台、采集上限、分析目标、AI 配置版本和系统模板版本。后续编辑不改变进行中运行、重试或历史报告。
- **R9 — Existing collectors.** 采集阶段复用现有多平台批次和搜索运行，不复制平台适配器或浏览器控制。全局内容仍按平台与平台内容 ID 去重，来源和本轮成员关系保持可追溯。
- **R10 — Per-task discovery.** 每个任务独立记录首次纳入的内容。同一内容先被任务 A 发现，不妨碍任务 B 后来第一次把它作为自己的新材料；同一任务后续再次采集到它时不重复进入自动报告材料。
- **R11 — Topic-neutral understanding.** 初步分析理解本轮新材料的正文、图片、视频和其他实际可用媒体，不按任务主题预筛。兼容的通用理解可以跨运行和任务复用，但必须保留实际输入、模型和模板版本。
- **R12 — Task-specific reporting.** 报告阶段只读取已保存的初步分析文本，以本次冻结的任务目标判断 `relevant`、`irrelevant` 或 `uncertain`。只有相关材料进入实质报告；不相关、不确定、输入不完整和技术失败分别保留。
- **R13 — One outcome per accepted run.** 有新材料时，在所有初步分析成员均已尝试后生成一次报告；成员部分失败不阻止使用成功材料生成报告，并展示未覆盖数量与原因。没有新材料时不调用 LLM，保存“本轮无新增舆情”的空报告并正常完成。
- **R14 — No approval gate.** 阶段之间没有人工审批。用户可以观察、取消或在失败后重试，但不能在正常推进中暂停并修改阶段输入。

### Concurrency, recovery and observability

- **R15 — No overlap for one task.** 同一自动任务最多一个活动运行。到期时上一轮仍活动，则持久化 `previous_run_active` 跳过记录；不排队、不补跑、不并行，下一未来计划时间再判断。
- **R16 — Different tasks stay durable.** 不同自动任务可以分别产生已接受运行；实际浏览器和 AI 工作继续服从现有全局资源互斥与串行队列，不通过并发绕过登录、媒体或模型租约。
- **R17 — Offline and clock recovery.** 应用离线、重启或系统时钟变化时不补跑错过轮次。系统记录可解释的错过信息并计算下一个未来时间；每日计划按冻结时区处理。
- **R18 — Cancel.** 取消整次运行会停止当前阶段并阻止后续阶段启动，同时保留已经提交的采集结果、初步分析和报告草稿/历史。取消本身不删除领域数据。
- **R19 — Resume from failure.** 每个阶段保留独立尝试。用户重试时沿用原运行冻结意图，复用全部成功阶段输出，从第一个失败阶段创建新尝试并继续后续阶段。报告失败重试不得重新采集、获取媒体或执行初步分析模型调用。
- **R20 — Truthful failure boundary.** 条目级失败和阶段级失败分开。成员已全部尝试且存在合法成功输出时可以继续；工作流基础设施失败、状态不确定或无法形成合法阶段输出时，阶段失败并等待显式重试。可能已计费的模糊模型请求不得自动重放。
- **R21 — Observable history.** 自动任务详情展示未来计划、跳过/错过记录、每次运行的阶段时间线、进度、输入数量、覆盖情况、错误、模型使用量和最终报告。读取、轮询或打开页面不会启动新工作。

### Replacement and compatibility

- **R22 — Central orchestration ownership.** 新工作流服务拥有自动推进权。采集、初步分析和报告服务继续作为可独立调用的领域执行器，但不再通过彼此的完成回调自动创建下一阶段。
- **R23 — Remove competing automatic path.** 旧定时采集产品接口、旧自动新内容准入和旧分析完成事件到报告的自动接力退出产品路径，避免两套机制重复推进。独立手动采集、手动初步分析、手动文本报告及其历史继续可用。
- **R24 — No legacy automation migration.** 不迁移旧定时采集计划、旧调度发生记录或旧自动接力状态。空数据库必须直接初始化为新结构；旧开发数据库可以在实施验证时重建，但本规划阶段不删除任何本地数据。
- **R25 — Preserve proven boundaries.** 不替换 SQLite、采集器、AI 供应商、媒体获取、严格 JSON/引用校验、使用量核算或已保存领域结果。数据库事务不得跨浏览器、网络或模型调用，错误不得泄漏内容、凭据、SQL 或本地路径。

## Acceptance Criteria

- [ ] **AC01 (R1–R5)** 用户可以创建默认停用的自动任务，配置规则、平台、数量、独立分析目标以及固定间隔或每日固定时间，并在启用前看到下一次执行时间。
- [ ] **AC02 (R2, R14)** 自动任务和运行界面不存在阶段开关、顺序编辑、跳过或中间审批入口。
- [ ] **AC03 (R6–R8)** 计划触发和“立即运行”都只创建一个冻结意图的工作流运行；立即运行不改变未来计划，重复/含糊提交通过请求标识幂等处理。
- [ ] **AC04 (R7, R21)** 每次运行显示采集、初步分析、相关性判断/报告的状态、输入范围、开始/结束时间、失败原因、关联领域记录和最终结果。
- [ ] **AC05 (R9–R10)** 任务 A 和任务 B 可以分别首次纳入同一全局内容；同一任务再次采集到它时不会重复作为该任务的新材料。
- [ ] **AC06 (R11–R12)** 文本、图文和视频条目进入同一初步理解链路；主题无关的兼容理解可以复用，但不同任务目标分别产生相关性判断和报告。
- [ ] **AC07 (R12–R13)** 关键词误命中的条目不进入实质报告；不相关、不确定、输入失败和技术失败均有可追踪结果，不能伪装为成功相关或成功不相关。
- [ ] **AC08 (R13)** 一轮有八条初步分析成功、两条失败时，系统在十条均已尝试后用八条成功文本生成一次报告，并展示两条未覆盖原因。
- [ ] **AC09 (R13)** 本轮没有该任务的新材料时，不调用分析或报告模型，保存“本轮无新增舆情”空报告并将运行标记为正常完成。
- [ ] **AC10 (R15)** 同一任务上一轮未结束时，下一到期轮次显示为“已跳过：上一轮仍在运行”，不创建排队运行且不影响上一轮。
- [ ] **AC11 (R16)** 不同任务同时到期时，各自触发记录不会丢失；执行服从现有浏览器和 AI 资源互斥，不产生重复拥有者。
- [ ] **AC12 (R17)** 离线跨过多个计划时间后不会集中补跑；重启只安排未来时间并留下可解释的错过记录。每日计划在时区边界行为确定。
- [ ] **AC13 (R18)** 取消运行后已完成领域结果仍可读取，当前拥有者被正确释放，未开始阶段不会继续执行。
- [ ] **AC14 (R19–R20)** 初步分析失败后的重试复用成功采集；报告失败后的重试不产生新的浏览器、媒体获取或初步分析模型调用，并保留每次尝试历史。
- [ ] **AC15 (R8, R19)** 运行期间修改任务目标、规则、计划或 AI 配置不会改写该运行；重试使用原冻结意图，新触发使用新配置。
- [ ] **AC16 (R21)** GET、页面进入、刷新、轮询和启动恢复均不会意外创建运行、重新采集或调用模型。
- [ ] **AC17 (R22–R23)** 旧采集完成→自动分析和分析完成→自动报告回调不再推进产品链路；只有工作流服务可以自动创建下一阶段，手动领域入口仍可独立使用。
- [ ] **AC18 (R24–R25)** 空数据库可初始化并完整运行新链路；验收不要求旧计划迁移，同时现有采集、分析、报告历史与安全边界没有被新编排器破坏。

## Out of Scope

- 新增舆论平台、替换 MediaCrawler 或改变平台登录方式。
- 训练自有模型、引入新的 AI 供应商或建立永久媒体归档。
- 通用工作流编辑器、自定义阶段、条件分支、每周/节假日计划和 Cron 表达式。
- 邮件、短信、企业微信等报告投递与通知。
- 旧定时计划、旧自动接力状态或本地开发数据库的数据迁移。
- 将来源陈述升级为已核实事实；报告仍是带来源和不确定性的模型分析。
