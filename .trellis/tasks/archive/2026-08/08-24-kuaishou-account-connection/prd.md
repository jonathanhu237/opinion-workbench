# 快手账号连接链路

## Goal

在现有本机单用户“平台账号连接中心”中接入快手真实账号连接闭环：用户从 React
页面发起检测，FastAPI 启动受控的 MediaCrawler 快手认证子进程，复用用户当前
Chrome，并以快手在线接口探针确认是否已登录。未登录或出现官方安全验证时，由用户
在可见 Chrome 中人工扫码或处理；系统只报告连接状态，不采集任何内容。

## Confirmed Product Decisions

- 本任务只接入快手账号连接，不实现快手关键词搜索、视频、作者、评论或媒体采集。
- 沿用现有借用用户 Chrome Profile 的方案；不复制 Profile，不把 Cookie、二维码、
  LocalStorage 或认证请求头写入前端、API、SQLite 或日志。
- 滑块、验证码和其他平台安全验证必须由用户在快手官方可见页面中人工完成，系统不
  自动识别、破解或拖动。
- 快手连接状态必须经过在线 `KuaiShouClient.pong()` 复检；`passToken`、状态文件或
  页面局部状态只能用于等待登录，不能单独产生“已连接”。
- 微博连接行为保持兼容；同一时刻仍只允许一个平台认证任务。
- 抖音、今日头条和小红书继续显示“暂未接入”，分别留给后续任务。
- 首版状态继续保存在当前 FastAPI 会话内，不为快手单独引入 SQLite。

## Requirements

### MediaCrawler authentication boundary

- `--type auth` 明确支持 `--platform wb` 和 `--platform ks`，其他平台继续拒绝；认证
  模式仍强制可见、借用现有 Chrome、loopback CDP、无代理、无显式认证状态持久化、
  无数据库/文件存储、无评论/媒体/词云。
- 快手认证流程发送现有版本化常量事件：等待浏览器、等待批准、检测中、等待人工
  登录、已连接或未连接；事件中的平台必须是 `ks`。
- 快手已有登录态时，在线探针通过后直接返回已连接，不打开登录框。
- 未登录时只打开快手官方可见页面并等待用户人工扫码或完成官方安全验证；不得提取、
  展示、转发或持久化二维码内容。
- 登录等待结束后更新内存 Cookie 并再次运行在线 `pong()`；只有在线探针成功才能发送
  `connected` 和退出码 0。
- 认证模式不得到达搜索、详情、作者、评论、媒体或存储入口；为这些入口增加失败哨兵
  测试。
- CDP 连接失败必须返回浏览器不可用类别，不得回退到标准或专属浏览器。
- 成功、失败、超时和取消都只关闭本任务创建的页面并释放 CDP 引用；不得关闭用户原有
  Chrome、Context 或标签页。
- 非认证的快手搜索/详情/作者模式保持现有行为兼容，包括原有二维码查看器和可选认证
  状态存取。

### FastAPI orchestration

- 后端从平台目录生成固定参数的认证命令，平台参数只能来自已启用的受信目录，不能由
  任意字符串拼接或通过 shell 执行。
- 认证事件模型允许 `wb | ks`，但每次尝试只接受与当前平台完全一致的事件；跨平台事件
  或未知字段必须使尝试安全失败且不得回显原始行。
- 快手从 `coming_soon` 改为 `enabled`，复用现有 202 启动、全局单任务锁、轮询、超时、
  取消、进程组清理和安全错误结构。
- 微博命令、协议序列、状态映射和真实回归行为不得改变。

### React connection center

- 快手条目提供与微博一致的“检测连接”操作，并复用现有 TanStack Query mutation、
  轮询、重复操作禁用和 live-region 状态播报。
- `action_required` 时明确提示用户前往已打开的快手官方 Chrome 页面扫码或人工处理
  安全验证，不暗示系统能自动通过滑块。
- 微博与快手可分别显示当前会话最近一次检测结果；其他三平台仍诚实显示“暂未接入”。
- 页面保持现有 shadcn 控制台、键盘操作、可见焦点、移动端 44px 目标和响应式行为。

## Out of Scope

- 快手搜索、采集、详情、作者、评论、媒体下载、调度、SQLite 持久化和舆情分析。
- 自动完成滑块、CAPTCHA、短信验证或规避平台安全机制。
- 抖音、今日头条或小红书连接适配。
- 专属 Chrome Profile、Cookie 导入导出或完全无人值守登录。
- 修改全局“一次只运行一个平台认证任务”的并发约束。

## Acceptance Criteria

- [ ] 页面同时提供微博和快手真实检测操作，其他三平台仍为不可操作的“暂未接入”。
- [ ] 已登录的用户 Chrome 能让快手在线探针直接返回“已连接”。
- [ ] 未登录时能打开快手官方可见页面，用户人工扫码/处理官方验证后在线复检为
  “已连接”。
- [ ] 人工操作未完成、Chrome/CDP 不可用、用户未批准、子进程协议错误及技术失败均
  产生准确、可重试且不泄密的页面状态。
- [ ] 快手认证模式没有任何内容采集或存储调用，并有自动化失败哨兵证明。
- [ ] 快手成功、失败、超时和后端关闭后，用户原有 Chrome 与预存标签页保持可用，仅
  任务创建的页面被关闭。
- [ ] 快手与微博尝试之间继续执行全局单任务互斥，重复点击不能产生并行浏览器会话。
- [ ] API、日志、测试夹具和前端状态中不包含 Cookie、二维码正文、认证 header、页面
  HTML 或原始子进程输出。
- [ ] MediaCrawler 定向/维护测试、FastAPI 测试、React 行为测试、静态检查和生产构建
  全部通过。
- [ ] 使用 loopback 前后端和真实 Chrome 完成快手成功路径及所有权回归，并只记录非
  敏感状态与资源计数。
