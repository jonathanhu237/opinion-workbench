# 两阶段提示词默认与自定义技术设计

状态：规划评审。产品行为以 `prd.md` 为准。

## 1. 方案概述

把“提示词默认值”从可修改的全局设置改为后端拥有的固定内置模板，并在所有用户入口统一使用一个严格的选择模型：`default` 直接采用内置模板，`custom` 从模板副本开始编辑并只属于当前自动任务或当前手工提交。

```text
后端固定内置模板
      |
      +--> 自动任务：保存两阶段 default/custom 选择
      |       `--> 每次运行冻结两份最终提示词
      |
      +--> 手工初步分析：本次选择内容理解提示词
      |
      `--> 手工报告：本次选择相关性与报告提示词
```

固定内置模板仍是业务指令，不包含可被用户覆盖的系统安全、证据、隐私、引用或 JSON 结构契约。前端从 API 读取模板用于展示与复制，不维护第二份硬编码文本。

## 2. 公共提示词契约

请求统一使用严格判别联合：

```json
{"mode":"default"}
```

或：

```json
{"mode":"custom","instructions":"……"}
```

`default` 禁止携带 `instructions`；`custom` 必须通过现有 1–8,000 字、非空、有效 UTF-8、无 NUL/代理字符校验。公开读取返回已解析快照：

```json
{
  "mode":"default",
  "version_id":1,
  "instructions":"……",
  "content_hash":"……",
  "schema_version":"initial-understanding-v1"
}
```

`mode` 表达本次选择来源，版本/哈希表达实际执行证据。自定义文本即使恰好等于默认文本也保留用户选择的 `custom` 来源，但缓存兼容仍按实际内容哈希判断。

`GET /api/v1/analysis-settings` 继续提供两份内置模板和自动分析授权状态，供手工操作与自动任务表单使用；删除 `PUT /analysis-settings/prompts/{stage}` 产品路由与前端客户端。现有自动分析授权 PUT 不变。

## 3. 持久化与 v18 迁移

保留 `analysis_prompt_versions` 作为不可变执行证据和缓存引用，不再把它当作用户可修改的全局设置。增加共享仓储助手，在一个数据库写事务内解析提示词选择：

- `default` 返回当前应用版本的规范内置提示词行；
- `custom` 按阶段、schema、内容哈希和完整文本复用相同不可变行，或创建新行；
- 哈希相同但完整文本不同时失败关闭，不用哈希碰撞替换内容。

v18 为 `automation_tasks` 增加两阶段的 `mode` 与 prompt-version 外键。为避免重建全部运行/发生记录的父表，新增列先允许迁移填充，再以插入/更新触发器强制非空、合法 mode、阶段匹配和 `analysis_goal` 与第二阶段文本一致。删除墓碑触发器同步纳入新字段，同时继续允许监控规则 `ON DELETE SET NULL` 的唯一例外。

迁移按以下规则处理既有数据：

1. 确保两份代码内置模板各有规范不可变版本行，并把 `analysis_settings` 的默认指针复位到这些行；旧自定义版本不删除。
2. 既有自动任务的第一阶段指向迁移前实际共享初步提示词；若内容等于内置模板标为 `default`，否则标为 `custom`，保证未来运行行为不突变。
3. 既有任务的 `analysis_goal` 解析为第二阶段不可变版本并标为 `custom`。
4. 已删除任务也填充新字段；迁移期间暂时替换并最终重建完整墓碑触发器。
5. 历史 job/report/run snapshot JSON、关联 ID、结果和使用量完全不改写。旧自动运行快照通过版本感知读取适配为新的两提示词公开投影。

`analysis_goal` 私有数据库列暂时保留为第二阶段文本镜像，以降低父表重建和 v17 删除触发器风险；新公共 API 不再使用这个含糊名称。新代码只通过统一任务 prompt 投影读写它。

## 4. 自动任务与运行

`AutomationTaskCreate/Replace` 用 `initial_prompt` 和 `report_prompt` 替代公开的 `analysis_goal`。创建/替换任务与解析自定义提示词版本在同一事务完成；任务修订号仍保护整份配置。

任务投影返回两份完整选择。每次运行接受时把以下内容冻结到新版 snapshot：

- 两阶段的 mode、prompt version ID、完整 instructions、content hash 与 schema version；
- 既有模型配置、规则、平台、数量和调度意图。

初步分析 child 使用冻结的第一阶段版本。报告 child 使用冻结的第二阶段 instructions 进行逐条相关性判断与树状报告写作。重试沿用原 snapshot；任务编辑、删除和应用重启均不能替换它。

旧 snapshot 保留 `analysis_goal` 与两个版本 ID；读取时将初步版本解析为旧版共享来源，将 `analysis_goal` 解析为任务自定义第二阶段，历史 JSON 不原地升级。

## 5. 手工流程

手工初步分析请求改为携带第一阶段 `PromptChoice`；后端在同一准入/幂等事务内解析不可变版本并写入 job。报告提示词不再出现在初步分析确认框中，因为该操作不会进行相关性判断或生成报告。job 详情显示实际内容理解提示词及 default/custom/legacy 来源。

手工报告创建把现有 `instructions_override` 表达收口为同一个第二阶段 `PromptChoice`。默认直接使用内置报告模板；自定义从模板复制并只冻结到该报告。报告技术重试默认沿用父报告提示词；“用其他提示词重新生成”仍是独立显式操作，可重新选择 default/custom。

请求证明包含完整 prompt choice，含糊网络响应继续使用同一 UUID 重放。提示词解析、job/report 创建和请求证明必须同事务提交，不能先创建一个可丢失的全局提示词设置。

## 6. 前端交互

新增产品级复用组件 `PromptChoiceField`，由 React Hook Form 控制，使用现有 shadcn `Field`、`Select` 与 `Textarea`：

- 始终提供可见标签、阶段说明和“使用默认 / 自定义”选择；不依赖 placeholder 充当标签或值。
- 默认模式显示完整只读模板和“切换为自定义”的清楚入口。
- 切到自定义时复制默认文本；自定义区显示字数与附近错误。
- 切回默认时实际提交 `default`，隐藏草稿不生效；同一未关闭表单内再次切回自定义可恢复草稿，关闭后不持久化。
- pending/含糊提交期间锁定选择和文本，保留既有反馈、确认与焦点契约。

自动任务编辑器展示“内容理解要求”和“相关性与报告要求”两个区块；后者明确同时负责相关性标准与最终报告重点。按钮保留已完成的“创建自动任务”文案。

手工初步分析确认框只展示第一阶段选择；手工报告表单使用第二阶段选择。`ResultsSettings` 删除两个全局 PromptEditor，仅保留并重新命名“新内容自动分析”授权区。运行、分析和报告详情显示冻结文本与来源。

UI/UX 检索支持使用有标签的 Select、RHF + Zod、FieldError 和提交反馈；没有为该具体模式找到专用 shadcn 组合，因此按项目现有表单原语实现，不新增状态管理或表单库。

## 7. 兼容、风险与回滚

- 第一阶段复用继续由 prompt content hash、schema、模型和输入共同决定；不同提示词绝不复用。相同文本即使来源 mode 不同仍可安全复用。
- 内置模板的未来代码改动必须增加明确版本并通过迁移引入；不得在启动时无条件改写现有任务或历史。
- 删除全局编辑入口不会删除旧提示词行。旧手工与自动历史仍通过原版本 ID 可读，并标注为旧版共享提示词。
- 新数据库版本对旧二进制实行既有前向拒绝。代码回滚需要 v17 数据库备份，不能只降低 `user_version`。
- 只使用临时 SQLite 和模拟 AI/采集做测试；不改写真实 `runtime/longtian.sqlite3`，不调用真实模型或平台。

## 8. 验证策略

- v17→v18：规范默认行、已编辑共享提示词、活动/停用/已删除任务、历史 run/job/report、失败回滚、重复初始化、前向版本与 FK/触发器完整性。
- 后端：PromptChoice 严格校验、默认/自定义原子解析、任务 CRUD/修订/删除、自动 snapshot 与重试、手工分析/报告幂等重放、缓存兼容与历史读取。
- 前端：严格解码、默认/自定义切换与草稿、两个自动阶段、手工阶段分离、全局编辑入口消失、pending/错误/含糊重试、详情来源展示。
- 完整运行后端 Ruff/pytest 与前端 format/lint/typecheck/Vitest/build；最后用临时数据库和本地浏览器检查自动任务、手工分析、手工报告与移动宽度，不提交真实 AI 或采集工作。
