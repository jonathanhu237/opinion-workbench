# 两阶段提示词默认与自定义

## Goal

让用户在自动任务和手工流程中分别理解并控制“每条来源如何被初步理解”和“哪些内容相关、最终报告如何呈现”，同时提供可直接使用的固定内置提示词，避免从空白开始编写。

## Background and Confirmed Facts

- 自动工作流固定为“采集 → 初步分析 → 相关性判断与报告”。现有任务表单只暴露一个 `analysis_goal`，其实际只在报告阶段作为任务专用指令使用，同时控制逐条相关性判断与报告写作。
- “AI 配置”页面只管理模型连接。当前可编辑的全局 `initial_prompt` 与 `report_prompt` 位于“结果与分析”页面的“提示词与自动分析设置”区域；本任务将退出这套用户可修改的全局默认入口，统一为固定内置模板加当前任务/当前操作自定义。
- 当前自动运行冻结默认初步分析/报告提示词版本，但第一阶段使用共享的默认初步分析提示词，报告阶段以任务的 `analysis_goal` 替代默认报告提示词。
- 既有设计刻意保持第一阶段主题中立，使相同输入、模型和提示词版本的内容理解可以跨运行、跨任务复用。允许任务自定义第一阶段后，只有解析后的提示词、模型和输入均兼容时才允许复用。
- 运行快照和重试必须继续使用运行接受时冻结的配置；之后编辑任务或系统默认提示词不得改写历史运行。
- 本轮讨论前已在 `main` 工作区把新建按钮从“创建停用的自动任务”改为“创建自动任务”，业务上仍默认停用；该小改动保留在本任务交付范围内。
- 此项产品决策替代早期自动工作流 PRD 中“系统提示模板不向自动任务用户开放编辑”的限制，但不改变固定阶段顺序。

## Requirements

- **R1 — Two explicit stages.** 自动任务编辑器分别展示“内容理解要求”和“相关性与报告要求”，用普通产品语言说明各自在工作流中的生效阶段。
- **R2 — Correct responsibility.** 第一部分只控制每条来源的摘要、地点/时间线索、媒体观察和不确定性等初步理解，不执行任务主题相关性筛选；第二部分同时控制 `relevant | irrelevant | uncertain` 判断标准与最终报告的关注重点/组织方式。
- **R3 — Fixed built-in defaults.** 两部分各有一份产品内置、不可由用户修改的固定默认提示词，用户无需从空白开始。默认内容必须是真实执行的模板，不能只用不会提交的灰色 placeholder 冒充默认值；修改内置模板属于未来明确的产品版本变更，不通过运行时设置传播。
- **R4 — Default/custom clarity.** 表单明确区分“使用默认”和“自定义”；切换到自定义时复制对应的固定内置模板作为可编辑起点，切回默认不得残留一个看似生效但实际未使用的草稿。
- **R5 — Unified manual behavior.** 手工初步分析和手工报告提交也分别提供“使用默认/自定义”；手工自定义从对应内置模板开始，只冻结到本次提交，不修改其他任务、之后的手工操作或系统默认。
- **R6 — Frozen execution.** 每次自动运行或手工提交接受时解析并冻结最终使用的提示词及其来源/版本/哈希。运行中编辑自动任务只影响之后的新运行；重试继续使用原运行快照或原手工提交意图。
- **R7 — Safe reuse.** 第一阶段理解结果只有在来源输入、模型、模板/引擎以及解析后的第一阶段提示词完全兼容时才能复用；任务或手工操作的自定义提示词不得错误复用由其他提示词生成的理解结果。
- **R8 — History and observability.** 自动运行、手工分析和手工报告详情可查看本次实际使用的提示词及其来源（内置默认或自定义），之后的任务编辑不改写历史。
- **R9 — Retire mutable global defaults.** “结果与分析”不再提供修改全局初步分析/报告默认提示词的设置入口；保留模型连接与自动分析开关等非提示词设置。
- **R10 — Existing workflow safety.** 不改变固定阶段顺序、采集规则、调度、取消、重试、软删除、报告证据和严格模型输出约束；用户提示词不能覆盖系统安全、结构、引用、隐私和证据约束。
- **R11 — Validation and migration.** 两阶段提示词继续使用现有非空 UTF-8、长度、NUL/代理字符和并发修订保护；现有自动任务和历史手工记录须无损兼容。
- **R12 — Plain create action.** 新建提交按钮显示“创建自动任务”，新任务默认停用的说明与成功反馈保持明确。

## Acceptance Criteria

- [ ] **AC1 (R1–R4)** 新建和编辑自动任务时可分别看到两个阶段的作用、默认/自定义状态和实际生效内容；新用户不输入提示词也能使用固定内置默认完成创建。
- [ ] **AC2 (R2)** 第一阶段自定义只改变来源理解输出，不进行相关性筛选；第二阶段自定义同时用于逐条相关性判断和报告生成。
- [ ] **AC3 (R3–R4)** 从默认切到自定义会复制固定内置模板供局部修改；恢复默认后运行使用内置模板而不是隐藏草稿，运行时设置变化不会改变该模板。
- [ ] **AC4 (R5)** 手工初步分析和手工报告在提交时都可直接使用内置默认，或从默认副本开始编辑本次自定义；完成后不会修改下一次操作的默认内容。
- [ ] **AC5 (R6, R8)** 每次自动运行、手工分析和手工报告详情显示实际冻结的提示词与来源；之后修改自动任务不改变该运行及其重试。
- [ ] **AC6 (R7)** 相同来源在兼容的默认/自定义提示词下可以复用；任一实际第一阶段提示词不同则不会复用旧理解结果。
- [ ] **AC7 (R9)** “结果与分析”不再存在可修改全局默认提示词的入口，内置默认不能被一次任务或一次手工提交改变。
- [ ] **AC8 (R10)** 监控规则仍独立决定采集范围；提示词编辑不会增加阶段、改变顺序或绕过固定安全与输出契约。
- [ ] **AC9 (R11)** 历史自动任务迁移后保持当前语义：第一阶段保留迁移前实际使用的共享提示词（与内置模板相同则记为默认，否则记为任务自定义），第二阶段保留原 `analysis_goal` 为自定义；历史手工分析、报告和自动运行不被改写。
- [ ] **AC10 (R11–R12)** 数据库/API/服务/运行快照、前端严格解码与表单交互均有回归测试；完整前后端质量门禁和本地浏览器验收通过，按钮显示“创建自动任务”。

## Out of Scope

- 让用户编辑系统安全提示、JSON 输出结构、引用规则、隐私边界或证据约束。
- 增加第三个独立的相关性提示词、通用工作流编辑器、阶段开关、顺序调整或条件分支。
- 改变监控规则、搜索词、平台、采集范围或模型供应商配置。
- 回写、重算或删除既有初步分析、报告和自动运行历史。
