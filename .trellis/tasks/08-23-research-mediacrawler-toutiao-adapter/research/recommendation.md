# 今日头条最小适配调研：工程结论与产品决策

日期：2026-08-23

## 工程调研结论

当前不应在 MediaCrawler 派生仓库中实现或运行今日头条站内搜索 adapter，任务结论应标记为“直接适配受准入条件阻塞”，而不是“技术不可行”。

原因按优先级如下：

1. `so.toutiao.com/robots.txt` 当前对所有 user-agent 声明 `Disallow: /`，`www.toutiao.com/robots.txt` 明确禁止 `/search`；MediaCrawler 自身源码声明要求遵守目标平台 robots.txt。
2. 今日头条官方公开能力中未找到可搜索任意公众内容的通用关键词 API；已确认的接口面向授权帐号的内容发布、视频列表和数据管理，不能覆盖公众投诉或媒体提及。
3. 网页端匿名搜索技术上能显示标题、摘要、来源、时间和跳转链接，但“浏览器能打开”不构成自动化准入依据。可见 DOM 和浏览器上下文网络响应都访问同一被禁止的搜索路径，后者也不能作为前者失败后的绕行。
4. 公开仓库中没有可直接复用的 MediaCrawler 今日头条实现。近期 Playwright 示例只能证明未来可能的模块边界，不能覆盖当前规则；其他候选要么只解析已知文章 URL，要么使用未公开接口、缺少源码/许可证，或只是第三方托管 API SDK。

## 2026-08-24 产品决策

用户明确不接受把直接适配标记为 `blocked`，决定在知悉上述 robots、官方能力和维护风险后继续实现。这是一项产品风险选择，不等于平台授权或工程调研结论发生变化。

实施范围因此限定为：项目专用可见浏览器、正常页面导航、DOM 读取、每关键词第一页、串行低频、无详情/评论、无私有 API、无签名逆向，并在验证码、滑块、403/429、登录墙或结构漂移时立即停止。详细合同以任务 `prd.md` 和 `design.md` 为准。

## 推荐路线

| 优先级 | 路线 | 当前动作 | 进入代码实现的门槛 |
| --- | --- | --- | --- |
| 1 | 官方开放能力、政务/媒体合作接口或书面许可 | 单独调研和申请，确认搜索范围、频率、字段、留存与链接使用权 | 文档或书面材料明确覆盖本项目的自动关键词搜索 |
| 2 | 合规数据供应商 | 单独评估合同、数据来源、覆盖率、价格、频率和数据留存 | 合同明确允许关键词发现以及结果链接在本系统中使用 |
| 3 | 人工搜索、人工录入链接 | 可作为本地 MVP 的临时输入方式 | 不自动访问头条搜索页；后端只做去重、分类、分级和通知 |
| 4 | 直接 DOM adapter | 用户决定继续，以实验性 search-only 范围实施 | 可见浏览器、单页低频、无私有网络接口；挑战或限制立即停止 |

## 对 MediaCrawler 的影响

- 进入实施阶段后在 `third_party/MediaCrawler` 新增完整、可测试的 search-only `toutiao` platform，不创建无行为的空壳模块。
- 父项目未来的 FastAPI/SQLite ingestion 应把“线索来源”与“平台 adapter”解耦，使人工链接和合规供应商数据能先进入统一的去重、AI 分类和通知流程。
- 若未来通过准入门，再按 `toutiao` 平台 ID 增加 factory/CLI/config、search-only crawler/client、最小 model/store 和离线测试；第一版不做正文、评论、creator/detail 或媒体下载。
- 是否需要 `login.py` 由获准的数据路径决定，不能为了目录对称预先实现。官方 OAuth 与浏览器 Cookie 也必须作为两套认证生命周期设计。

## 重新评审触发条件

满足任一条件后可以重新调研，而不是直接复用旧页面结论：

- 获得官方文档化的通用公众内容搜索 scope；
- 获得明确覆盖自动化搜索路径、频率和数据使用的书面许可；
- robots/服务条款发生可验证变化；
- 选定合同明确授权的数据供应商。

重新评审仍应以一个关键词、单页、可见浏览器、无自动验证码处理、无签名逆向为上限；出现 CAPTCHA、滑块、403/429、登录墙或规则冲突时立即停止。
