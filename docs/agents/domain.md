# Domain Docs

本仓库采用 single-context 布局。

## 探索代码前

- 阅读根目录 `CONTEXT.md`。
- 阅读 `docs/adr/` 下与当前工作有关的架构决策记录。
- 文件不存在时直接继续，不提示缺失，也不预先要求创建。
- `/domain-modeling` 在领域术语或决策得到明确后按需创建这些文档。

## 文件布局

- `CONTEXT.md`：项目领域上下文和术语表。
- `docs/adr/`：按编号保存架构决策记录。

## 使用统一术语

在任务标题、重构建议、假设和测试名称中，使用 `CONTEXT.md`
定义的领域术语，避免使用术语表明确排除的同义词。

若术语尚未收录，先判断是否符合项目现有语言；确属缺口时，
记录下来供 `/domain-modeling` 处理。

## 显式指出决策冲突

如果建议与现有 ADR 冲突，应明确指出相关 ADR 及重新讨论的理由，
不得静默覆盖已有决策。
