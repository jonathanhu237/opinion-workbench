# Windows 单机安装包与本地构建工具包

Status: open
Labels: ready-for-agent

> 后续范围修订：用户已确认 [Windows 与 macOS 便携 ZIP 及 GitHub Release 发布](../portable-desktop-release/spec.md)。新规格取代本文的安装器主交付、系统用户数据目录和排除云端 CI 构建三项决定；本文保留为历史实现依据，生命周期、业务及凭据安全要求继续有效。后续发行按新规格实施，不重复领取本文已完成部分。

## Problem Statement

使用者希望把现有舆情系统交给姐姐在 Windows 电脑上日常使用。当前项目需要配置 Python、Node、包管理器并分别启动前后端，非技术使用者难以操作；浏览器控制、凭据存储和部分迁移逻辑还依赖 macOS/POSIX，直接复制源码无法交付。维护者主要使用 Mac，但有一台 Windows 可以执行构建及真实验证，不希望重新安装和配置整套 Codex。

## Solution

提供两个面向不同使用者的产物：维护者在 Windows 运行的构建工具包，以及姐姐使用的 Windows 安装程序。开发在 Mac 上完成；构建入口尽量自动检查和准备所需工具、安装锁定依赖并生成安装程序，失败时留下可反馈的日志。构建工具仅安装在维护者电脑。

姐姐安装后双击桌面快捷方式，自动启动本机服务并打开普通浏览器中的系统页面。首次由维护者协助安装 Chrome、配置 AI 服务和登录平台。首次业务库为空；后续手动覆盖安装保留业务资料、配置和登录资料。无需命令行、托盘、独立桌面窗口或开机启动。

最后一个系统页面断开心跳约 10 秒后，停止采集和报告生成并退出后台。刷新和短暂重连不应误停。下次启动显示此前任务已中断，不自动恢复，由使用者重新发起。

## User Stories

1. 作为维护者，我希望在 Mac 上完成开发，以便沿用已有工作环境。
2. 作为维护者，我希望在自己的 Windows 上运行构建入口，以便生成 Windows 安装包。
3. 作为维护者，我希望无需重新配置 Codex、插件和技能，以便减少准备工作。
4. 作为维护者，我希望构建入口检查系统版本、架构和依赖，以便提前识别不支持的环境。
5. 作为维护者，我希望构建入口尽量自动准备工具和依赖，以便减少手工命令。
6. 作为维护者，我希望下载或构建失败后得到明确原因和日志，以便反馈问题并重试。
7. 作为维护者，我希望能清楚找到生成的安装程序，以便发给姐姐。
8. 作为使用者，我希望通过安装程序创建桌面入口，以便像普通软件一样启动系统。
9. 作为使用者，我希望无需安装 Python、Node 或开发工具，以便直接使用。
10. 作为使用者，我希望双击入口就自动打开本地网页，以便无需手动启动服务或输入地址。
11. 作为使用者，我希望初次打开是空白业务库，以便不会混入开发者的内容和报告。
12. 作为维护者，我希望协助完成首次 AI 配置和平台登录，以便姐姐后续独立操作。
13. 作为使用者，我希望缺少 Chrome 时得到可操作的提示，以便完成必要准备。
14. 作为使用者，我希望采集使用专用 Chrome 登录资料，以便日常浏览器不被接管。
15. 作为使用者，我希望重启后保留有效的平台登录状态，以便无需每次登录。
16. 作为使用者，我希望 AI 配置能在 Windows 正常保存和读取，以便后续生成报告。
17. 作为使用者，我希望现有五平台舆情爬取和文字理解流程继续可用，以便完成日常业务。
18. 作为使用者，我希望平台要求扫码或安全验证时保留既有待人工处理流程，以便完成操作后显式继续采集。
19. 作为使用者，我希望刷新系统页面不会停止任务，以便正常操作网页。
20. 作为使用者，我希望仍有其他系统页面打开时后台继续运行，以便多页面使用不互相误停。
21. 作为使用者，我希望关掉最后一个系统页面后程序自动停止，以便不必寻找托盘或终端退出。
22. 作为使用者，我希望退出时停止正在进行的采集和报告生成，以便关闭页面后不继续执行工作。
23. 作为使用者，我希望已经保存的内容和报告不因退出丢失，以便继续查看历史资料。
24. 作为使用者，我希望再次打开能看到未完成任务已中断，以便理解上次操作的结果。
25. 作为使用者，我希望中断任务不会自动恢复，以便由我决定何时重新发起。
26. 作为使用者，我希望覆盖安装新版后保留数据、配置和登录资料，以便升级不必重新开始。
27. 作为维护者，我希望安装包不包含开发数据库、密钥或登录资料，以便交付干净的应用。
28. 作为维护者，我希望在自己的 Windows 上完成实际验收，以便确认姐姐收到的是可用程序。

## Implementation Decisions

- 保留 React 静态前端、FastAPI 后端与 SQLite 的本地应用结构。由同一本地服务提供构建后的前端和现有 API，服务只监听本机回环地址。交付运行不依赖前端开发服务器。
- 增加应用启动入口，负责后台启动、就绪检测、打开系统页面和完整退出。处理重复启动、端口占用和浏览器未成功打开等失败情况，避免留下无入口的后台进程。具体机制由实施选择，不引入托盘或独立桌面壳。
- 页面生命周期采用多页面心跳租约；最后一份租约失效约 10 秒后进入退出流程。退出期间停止接收新任务，并停止应用拥有的采集、报告及相关子进程。关闭应用管理的专用浏览器，保留其登录资料，不关闭日常浏览器。
- 心跳计时采用可靠时钟并考虑刷新、后台标签页节流、浏览器冻结和电脑休眠。不能仅凭关闭事件判断退出，也不能宣称网页心跳能绝对区分关闭与冻结。实现若不能满足已确认的约 10 秒体验，需报告限制，不静默改成永久后台运行。
- 启动后此前中断的采集和报告不得自动恢复；持久化状态应能显示“已中断”。优先复用现有状态及展示映射，仅在确有需要时做兼容迁移。已保存的舆情内容、单条总结和已完成报告保留。平台验证导致的“待人工处理”与应用退出导致的中断保持区分。
- 不新增开机自动运行；现有应用内自动任务不得绕过退出流程或重新激活已中断任务。不扩展现有调度产品能力。
- 将数据库、配置、凭据、浏览器资料和诊断资料放入稳定的 Windows 用户数据位置，独立于安装目录和临时解包目录。覆盖安装保留这些资料。初装建立空白业务库，不导入开发环境数据。
- 适配 Chrome 的 Windows 安装位置发现、进程控制、单实例协调及文件访问。保持专用浏览器隔离，不通过复制日常浏览器 Cookie 实现登录。
- 适配 Windows AI 凭据保存与读取，保持密钥不经普通设置响应或日志泄露的契约。具体 Windows 保护机制由实施确定，不照搬 POSIX 权限检查，也不以取消隔离校验代替适配。
- 修正数据库初始化和历史媒体清理中的 POSIX 专用依赖，使新 Windows 数据库能初始化。遵守既有媒体退出决定：不恢复媒体能力，不删除无法证明归属的资料。
- 按已讨论的 Python 冻结打包方向准备 Windows 构建，包含前端静态产物、Python 运行依赖和 Playwright 必需运行组件；采集浏览器使用目标机 Chrome。冻结程序中的动态资源和必要子进程调用必须验证，不能假设冻结后的可执行文件仍是 Python 解释器。
- 构建工具包使用现有依赖锁定信息，提供明确入口、进度、错误和产物位置。新增开发工具按仓库约定优先使用 mise 管理；安装确认和网络问题仍可能要求维护者操作。
- 发布产物为安装程序，创建桌面快捷方式；升级由维护者发送新安装包，使用者覆盖安装。安装器具体选型及支持的 Windows 版本/架构在实施时明确，并由构建入口校验，不假设所有 Windows 均可用。
- Windows 上实际构建与验收；Mac 上继续开发和适用回归验证。不使用 Centaurus，不引入云端构建，不要求 Windows 安装 Codex。

## Testing Decisions

- 用户已确认测试以 Windows 安装后应用为最高边界，覆盖启动网页、配置与采集、报告生成、关闭退出、重开和覆盖升级。新增的主要测试入口是安装后的应用启动入口，尽量不新增分散的内部测试接口。
- 好的测试断言外部可见结果：页面可用、API 可达、数据保留、任务停止、进程退出和中断状态；不固定内部函数调用顺序、私有字段或安装器实现细节。
- 复用现有应用工厂和 TestClient 集成测试、临时 SQLite 数据库、假浏览器/操作系统边界及假 AI 响应。现有健康检查、Chrome 生命周期、AI 设置、采集恢复、报告取消和媒体退出测试提供先例。离线回归不得触碰真实用户资料或调用付费 AI。
- Windows 实测安装到干净用户数据环境；即使构建机装有开发工具，也需验证运行不依赖其 Python、Node、源码目录或开发环境 PATH，防止“只能在构建机运行”。
- 验证首次安装空白业务库、桌面入口自动打开、静态资源和页面刷新可用、后台只监听本机、重复启动和启动失败有可操作结果。
- 验证 Chrome 缺失提示、专用窗口打开、平台登录状态跨重启保留、AI 配置保存和连通性；验证五平台现有业务入口，真实平台受限时记录验证缺口，不能将假响应测试声称为实网通过。
- 在采集和报告生成分别运行时验证关闭最后页面后约 10 秒开始停止与退出；保留已提交资料，停止后不继续发起平台操作或 AI 请求。已发到外部服务的请求不能承诺撤回或退还费用。
- 验证刷新、短暂断线、多页面仅关一个、后台标签页、休眠与恢复；页面仍有效时不得因普通后台节流误退出。验证退出后的专用浏览器和后台进程清理。
- 重开验证中断任务可见且不自动恢复，手动新任务可正常执行；平台待人工处理流程仍须显式继续，不被新生命周期语义混淆。
- 覆盖升级验证数据库、报告、AI 配置和浏览器资料保留；检验新包中不含开发数据、密钥和登录资料，日志不含敏感凭据。
- 验证构建工具缺失、下载失败、不支持系统、包含中文或空格的目录和构建失败日志；重试不应破坏用户数据。
- 运行与适配有关的后端回归及前端类型、构建和生命周期测试。维护者在自己的 Windows 执行真实验收并反馈；在拿到结果前必须明确 Windows 验收尚未完成。

## Out of Scope

- 多用户交付、团队共享、服务器部署、Centaurus 和云端 CI 构建。
- Electron/Tauri 等独立桌面窗口、托盘、开机启动和关闭页面后长期运行。
- 自动更新、无人值守的全天采集和中断任务自动续跑。
- 开发数据迁移、复制开发者平台登录态或随包分发 AI 密钥。
- 要求姐姐安装开发工具，或要求维护者重配 Windows Codex。
- 重做舆情业务界面、扩展平台范围、恢复媒体缓存、下载或多模态分析。
- 本规格不增加数据导入导出、云备份、跨设备同步或远程诊断服务。

## Further Notes

本规格整理自已经完成的讨论。Q5 最初的托盘后台运行建议已被用户明确推翻，以关闭最后一个页面后停止并退出为准。Windows 本地构建方案已确认；此前云端构建只是讨论过的替代项，不属于当前方案。

遵守现有关于人工操作后显式继续、报告选材、原帖文字理解和媒体退出的架构决定。当前安装交付不改变这些业务边界，不向领域术语表添加打包实现术语。

当前仅发布规格，未获实施请求，不修改产品代码。最终交付应包含 Windows 安装程序、维护者构建工具包、简短构建与首次配置说明和验收结果；真正的 Windows 安装包须在 Windows 构建成功后才能称为已交付。
