# 报告生成页面重构

Status: open

Labels: ready-for-agent

## Problem Statement

当前“结果与分析”页面把舆情内容库、自动分析设置、报告选材、两套提示词、全库处理规则、当前任务、历史任务、旧单条处理记录和独立报告纵向堆在同一页面。使用者进入页面后难以判断主要目标、下一步操作以及当前看到的是内容状态、任务状态还是报告状态。

这套界面也没有遵守已经确定的两阶段业务语言。舆情爬取负责发现内容并入库，报告生成负责从舆情内容库选材、必要补全、单条总结和汇总报告；但当前导航仍使用含义宽泛的“结果与分析”，列表使用“全部采集结果”和“初步分析状态”等旧称谓，自动任务的授权设置也混入手动报告流程。

现有批量入口会直接创建报告生成任务，而使用者希望它只帮助选材：逐条勾选和批量选中都先形成一个可见、可修改且固定的来源集合，之后再通过唯一的“生成报告”操作填写报告名称和两套提示词并确认提交。报告执行、历史阅读和异常恢复也应集中在一个报告记录入口中，不再暴露新旧两套工作流。

## Solution

将左侧“结果与分析”改为“报告生成”，页面以生成一份报告为核心，并继续展示全部舆情内容作为报告选材来源。页面内部使用“生成报告”和“报告记录”两个页签：“生成报告”使用 Shadcn 风格的 Data Table 完成浏览、跨页选材和内容详情查看；“报告记录”集中展示当前任务、历史任务、报告正文、来源覆盖和恢复操作。

首版不提供内容筛选。内容表格按最新入库优先，每页二十条；表头全选只控制当前页。用户可以逐条勾选，也可以通过“选中全部待分析内容”把整个内容库中当时符合条件的待分析条目加入当前选材，并通过次级选项明确加入分析失败条目。批量选材在点击时形成固定集合，不覆盖已有手选内容，不自动吸收后来入库的内容，并允许用户排除其中任意条目。

页面底部固定显示选材栏。点击唯一的“生成报告”按钮后打开确认弹窗，系统按日期预填可编辑的报告名称，上下展示带默认值的“内容理解提示词”和“报告生成提示词”，并允许恢复默认值。弹窗展示待分析、已有总结、失败重试等选材数量以及只读模型信息；提示词修改只对本次报告生效。自动分析授权、模型编辑、媒体设置、报告时间范围、汇报对象和报告格式不进入该弹窗。

任务成功创建后清空选材草稿，自动切换到“报告记录”并打开新任务。任务按“补全内容、生成单条总结、汇总报告、完成”展示阶段和条目数量。首版同一时间只允许一份报告生成，但活动任务期间仍可浏览内容并准备下一份选材。完成的报告直接在报告记录中阅读；旧报告归入同一记录列表，旧单条处理历史进入对应内容详情，不删除历史数据。

## User Stories

1. 作为舆情分析人员，我希望左侧入口叫“报告生成”，以便它与“舆情爬取”共同表达产品的两个业务阶段。
2. 作为舆情分析人员，我希望进入页面后明确知道主要目标是生成报告，以便不必先理解系统内部任务结构。
3. 作为舆情分析人员，我希望在报告生成页面看到全部舆情内容，以便从历次积累的数据中选材。
4. 作为舆情分析人员，我希望内容库只是报告选材来源而不是第三个业务阶段，以便保持产品心智模型简单。
5. 作为舆情分析人员，我希望自动分析设置不出现在手动报告页面，以便不会混淆自动任务和本次报告。
6. 作为自动任务管理者，我希望自动分析授权仍归自动任务管理，以便自动化配置有唯一入口。
7. 作为舆情分析人员，我希望在“生成报告”页签准备下一份报告，以便选材操作集中在一个工作区。
8. 作为舆情分析人员，我希望在“报告记录”页签查看任务和报告，以便准备工作与已提交工作不再纵向混杂。
9. 作为舆情分析人员，我希望页面默认使用清晰的表格展示内容，以便快速扫描大量记录。
10. 作为舆情分析人员，我希望首版没有尚未证实必要性的筛选控件，以便页面保持聚焦。
11. 作为舆情分析人员，我希望内容按最新入库优先排列，以便优先看到最近发现的信息。
12. 作为舆情分析人员，我希望表格每页显示二十条内容，以便页面性能和浏览范围保持稳定。
13. 作为舆情分析人员，我希望翻页后此前勾选的内容仍然保留，以便跨页组合报告来源。
14. 作为舆情分析人员，我希望表头全选只选择当前页，以便不会无意选中未查看的全库内容。
15. 作为舆情分析人员，我希望跨全库选材使用名称明确的按钮，以便它不会与当前页全选混淆。
16. 作为舆情分析人员，我希望逐条勾选任意内容，以便精确决定报告来源。
17. 作为舆情分析人员，我希望一键选中全部待分析内容，以便快速处理积压内容。
18. 作为舆情分析人员，我希望批量选材默认排除分析失败条目，以便不会意外重试历史失败。
19. 作为舆情分析人员，我希望通过明确的次级选项加入分析失败条目，以便需要时可以集中重试。
20. 作为舆情分析人员，我希望批量选材加入而不是覆盖已经手选的内容，以便不会丢失之前的选材成果。
21. 作为舆情分析人员，我希望批量选中后仍能取消任意条目，以便排除不适合本次报告的内容。
22. 作为舆情分析人员，我希望批量选材在点击时固定实际集合，以便后续新增内容不会改变我看到的选材数量。
23. 作为舆情分析人员，我希望选材本身不会启动分析，以便确认范围前不会访问平台或调用模型。
24. 作为舆情分析人员，我希望表格显示平台、内容摘要、素材、发布时间和分析状态，以便不打开详情也能完成大部分判断。
25. 作为舆情分析人员，我希望素材列区分正文、图片、视频和缺失情况，以便了解报告可能使用的材料。
26. 作为舆情分析人员，我希望分析状态使用“待分析”“已总结”“分析失败”等明确词汇，以便区分从未处理和历史失败。
27. 作为舆情分析人员，我希望首次发现时间和采集次数放在详情中，以便主表格不过度拥挤。
28. 作为舆情分析人员，我希望从右侧打开内容详情，以便保留当前分页和选材上下文。
29. 作为舆情分析人员，我希望内容详情展示完整正文、图片、视频、总结和处理记录，以便核查选材依据。
30. 作为舆情分析人员，我希望内容详情中的原文操作仍然可用，以便必要时核对平台来源。
31. 作为舆情分析人员，我希望页面底部持续显示已选数量，以便滚动和翻页时仍知道当前选材规模。
32. 作为舆情分析人员，我希望固定选材栏只提供清空和“生成报告”等必要操作，以便下一步明确。
33. 作为舆情分析人员，我希望点击“生成报告”后才填写本次报告信息，以便选材和提交相互独立。
34. 作为舆情分析人员，我希望系统自动填写带日期的报告名称，以便不必为普通报告反复命名。
35. 作为舆情分析人员，我希望可以修改预填的报告名称，以便创建专题化、可识别的报告。
36. 作为舆情分析人员，我希望上下看到内容理解和报告生成两套提示词，以便分别控制单条总结与最终报告。
37. 作为舆情分析人员，我希望两套提示词都有系统默认值，以便不需要每次从空白开始编写。
38. 作为舆情分析人员，我希望可以恢复默认提示词，以便撤销本次临时修改。
39. 作为舆情分析人员，我希望提示词修改只影响本次报告，以便专题要求不会悄悄改变后续默认行为。
40. 作为舆情分析人员，我希望确认弹窗展示选中总数及待分析、已有总结和失败重试数量，以便理解真实工作范围。
41. 作为舆情分析人员，我希望确认弹窗只读展示将使用的模型，以便提交前知道内容发送到哪里。
42. 作为舆情分析人员，我希望弹窗明确提示可能发生模型调用，以便理解本次操作可能产生用量。
43. 作为舆情分析人员，我希望大批量选材显示真实数量和需要处理的规模，以便在没有武断上限的情况下作出知情确认。
44. 作为舆情分析人员，我希望关闭弹窗不会清空选材，以便可以返回继续调整。
45. 作为舆情分析人员，我希望提交失败不会清空选材，以便修正问题后重试同一份报告。
46. 作为舆情分析人员，我希望页签切换和浏览器刷新后仍保留选材草稿，以便意外刷新不会丢失工作。
47. 作为舆情分析人员，我希望任务成功创建后才清空选材草稿，以便不会因含义不确定的提交结果丢失来源集合。
48. 作为舆情分析人员，我希望成功提交后自动进入新任务，以便立即看到报告是否开始处理。
49. 作为舆情分析人员，我希望任务展示补全内容、生成单条总结、汇总报告和完成四个阶段，以便知道当前正在进行什么。
50. 作为舆情分析人员，我希望任务展示总数、待处理、处理中和失败数量，以便判断整体进度。
51. 作为舆情分析人员，我希望完成后看到哪些条目新生成总结、哪些复用了总结、哪些失败，以便核对实际处理结果。
52. 作为舆情分析人员，我希望同一时间只运行一份手动报告，以便避免本地浏览器、登录态和模型调用相互争用。
53. 作为舆情分析人员，我希望活动任务期间仍能浏览内容并准备选材，以便等待过程中可以继续工作。
54. 作为舆情分析人员，我希望活动任务结束前不能提交另一份报告，以便不会无意建立隐藏队列。
55. 作为舆情分析人员，我希望进入报告记录时优先打开活动任务，以便最需要处理的状态首先可见。
56. 作为舆情分析人员，我希望没有活动任务时自动打开最新报告，以便快速查看最近成果。
57. 作为舆情分析人员，我希望报告列表显示名称、状态、创建时间和选材数量，以便快速定位历史报告。
58. 作为舆情分析人员，我希望报告正文、覆盖情况和来源直接显示在报告记录中，以便任务完成处就是交付处。
59. 作为舆情分析人员，我希望可以取消运行中的任务并保留已完成成果，以便控制本机资源和模型消耗。
60. 作为舆情分析人员，我希望任务因登录或安全验证暂停时能打开专用窗口并显式继续，以便由我控制恢复时机。
61. 作为舆情分析人员，我希望报告生成失败时只重试报告，以便复用已完成的材料和单条总结。
62. 作为舆情分析人员，我希望个别条目失败不阻止其他内容生成报告，以便仍能获得基于可用来源的结果。
63. 作为舆情分析人员，我希望失败条目保留在本次来源处理结果中，以便报告不会掩盖未处理材料。
64. 作为舆情分析人员，我希望没有足够相关内容被显示为正常空结果，以便不会误认为系统执行失败。
65. 作为舆情分析人员，我希望旧报告进入统一的报告记录，以便历史成果仍然可读。
66. 作为舆情分析人员，我希望旧单条处理历史进入对应内容详情，以便必要时可追溯但不干扰主流程。
67. 作为舆情分析人员，我希望旧数据不会因为页面重构而被删除，以便历史成果保持完整。
68. 作为键盘使用者，我希望页签、表格选择、详情和弹窗具有明确焦点顺序，以便不使用鼠标也能完成操作。
69. 作为键盘使用者，我希望关闭内容详情后焦点回到原表格行，以便继续选材而不迷失位置。
70. 作为使用辅助技术的人员，我希望任务状态、选中数量和错误提示具有正确语义，以便及时理解页面变化。

## Implementation Decisions

1. 导航和页面身份统一使用“报告生成”；“结果与分析”“全部采集结果”和“初步分析”等旧界面词汇分别改为“报告生成”“舆情内容”和“分析状态”等领域语言。
2. 页面划分为“生成报告”和“报告记录”两个页签。页签状态应可被刷新和直接链接恢复；指定任务或报告的链接应进入“报告记录”并打开对应详情。
3. 自动分析设置组件从手动报告页面移除。自动分析授权与配置继续由自动任务相关界面拥有，不复制到报告弹窗。
4. 舆情内容使用 Shadcn Data Table 模式实现。复用现有 Table、Checkbox、Badge、Tabs、Sheet、Dialog、Pagination 等组件；需要排序、分页和跨页行选择状态时可引入 TanStack Table，但不把其客户端行模型当成全库数据源。
5. 首版不展示平台、状态、日期或文本筛选。数据按首次入库时间倒序读取，使用服务端分页，每页固定二十条。
6. 表格列固定为选择、平台、内容摘要、素材、发布时间、分析状态和操作。摘要最多显示两行；素材显示可用正文、图片数、视频数和缺失状态；操作只保留查看详情与打开原文。
7. 表头复选框只切换当前页可选择的记录，并使用半选状态表达当前页部分选中。活动任务占用或其他不可选记录不被表头操作错误纳入。
8. 客户端维护当前选材草稿。逐条选择、当前页全选和批量选材都合并进同一个去重集合；任何方式选中的条目都可以手动排除。
9. 增加一个只形成选材快照的业务操作，用于取得点击时全部待分析条目的具体身份和状态数量；它不得创建分析任务、访问平台、下载媒体或调用模型。次级模式在同一快照中明确加入当前分析失败条目。
10. 批量选材快照覆盖整个舆情内容库，因为首版没有筛选。快照返回后加入已有草稿，后来入库的内容不自动加入。提交报告时发送固定的具体来源集合，而不是重新求值“当前全部待分析”。
11. 批量选材主按钮立即加入待分析条目；相邻的次级菜单提供“同时加入分析失败内容”。不在页面常驻一个难以理解的失败项复选框。
12. 选材草稿保存在当前浏览器会话中，使页签切换、路由变化和刷新可以恢复。关闭弹窗、读取失败或明确的提交失败不清空；任务创建被服务端确认成功后清空。应用重启后的长期草稿恢复不作保证。
13. 页面底部使用固定选材栏，持续显示选中数量，并提供清空与“生成报告”主操作。没有选材、模型未配置或已有活动任务时，提交操作禁用并解释原因。
14. 报告确认弹窗包含报告名称、内容理解提示词、报告生成提示词、选材状态数量、只读模型信息及模型调用提醒。它不包含自动化授权、模型编辑、媒体设置、时间范围、汇报对象或报告格式。
15. 报告名称成为报告生成意图的持久字段。新报告按本地日期预填“YYYY-MM-DD 舆情分析报告”并允许编辑；旧记录没有名称时使用稳定的兼容名称，不修改原历史事实。
16. 两套提示词均从系统维护的默认模板开始。用户编辑后按本次自定义提示词提交；“恢复默认”恢复当前系统默认，不把本次输入写回全局默认或下一份报告。
17. 报告创建继续使用客户端生成的幂等请求标识。模糊提交重试必须保持报告名称、两套提示词、模型版本和固定来源集合不变，避免重复任务及重复模型调用。
18. 报告创建在数据库事务中固定来源、报告名称、提示词版本和模型版本。页面读取或刷新不能创建任务、重新求值批量范围或启动外部操作。
19. 报告生成准入增加“同一时间只有一份活动手动报告”约束。活动任务存在时仍允许读取舆情内容和编辑草稿，但新的提交收到稳定、可理解的冲突结果，不建立隐藏队列。
20. 成功创建任务后导航到“报告记录”页签并选中新任务。当前任务根据实际子状态映射为补全内容、生成单条总结、汇总报告和完成，不伪造不能计算的百分比。
21. 报告记录使用简洁列表加全宽详情。存在活动任务时默认选中活动任务；否则默认选中最新报告。列表至少返回名称、状态、创建时间和固定选材数量。
22. 报告详情继续展示任务数量、新总结、复用总结、失败条目、报告覆盖、报告正文和来源；报告完成后不要求跳入第二套“独立报告”界面才能阅读。
23. 取消、人工暂停、显式继续、配置阻塞、执行中断、报告失败和正常空结果沿用已有持久状态及并发修订保护，但统一在报告记录详情中呈现。
24. 报告阶段失败的重试继续复用成功的单条总结和已完成报告步骤，不重新搜索、补全或逐条总结。个别来源失败不会终止其余可用来源的报告。
25. 旧报告通过兼容投影进入统一报告列表和详情。旧单条处理任务不再作为主页面独立工作流展示，其尝试与错误记录由对应内容详情读取；迁移不删除旧报告、总结、来源或尝试记录。
26. 内容详情使用右侧 Sheet，并包含正文、实际媒体状态、单条总结、处理尝试和来源信息。关闭后恢复到触发详情的表格行，并保持分页与选材草稿。
27. 所有表格、页签、Sheet、Dialog、菜单、进度和状态提示遵循项目现有 Shadcn Base UI 组合方式，使用语义化颜色、组件状态和可访问名称，不通过自定义样式伪造已有组件。
28. 现有“全库待处理”直接创建任务的界面行为被替换为“形成选材快照”。旧服务端规则可用于兼容读取历史意图，但新页面提交统一使用可核对的固定来源集合。
29. 页面重构不改变舆情爬取、正文与媒体补全、模型调用、报告相关性判断和媒体保留的业务实现；只调整报告入口、选材意图、名称持久化、单活动任务准入及历史呈现。

## Testing Decisions

1. 主要测试入口是完整的“报告生成”页面行为。测试从用户进入页面开始，操作真实的页签、表格、复选框、批量选材、详情 Sheet、固定操作栏和报告弹窗，再观察请求意图、任务进度与报告交付；不针对私有组件拆分或内部 hook 调用顺序写断言。
2. 页面测试沿用现有应用路由测试方式：使用真实路由、查询缓存和组件组合，替换本机数据请求与模型、浏览器等外部效果。测试描述为用户可见操作，不要求用户理解所谓“应用 API”。
3. 覆盖导航改名、默认页签、直接链接进入指定任务、页签切换和刷新恢复，确保“报告生成”成为唯一手动报告入口。
4. 覆盖表格每页二十条、最新入库优先、两行摘要、素材状态、分析状态、当前页全选、半选状态以及不可选记录处理。
5. 覆盖跨页逐条选材，验证返回上一页后勾选仍存在，关闭详情和切换页签不会改变集合。
6. 覆盖批量选材默认只加入待分析条目、次级选项加入分析失败条目、与已有手选集合合并、用户排除个别条目以及后来入库内容不加入既有快照。
7. 在业务服务与临时 SQLite 数据库层验证批量选材快照的原子性和无副作用：形成快照不创建报告任务、不改变条目状态，也不启动平台或模型调用。
8. 覆盖选择草稿的会话恢复、清空、关闭弹窗、提交失败和成功提交行为。只有服务端确认创建后才清空；模糊结果继续复用同一请求标识和固定意图。
9. 覆盖弹窗自动报告名称、可编辑名称、两套默认提示词、自定义提示词、恢复默认、选材数量拆分、只读模型信息和费用提醒。
10. 在迁移与仓储层验证报告名称持久化、旧记录兼容名称、列表排序和任务详情一致性；旧数据库升级失败必须整体回滚。
11. 覆盖活动任务存在时仍可浏览和选材但不能提交第二份报告，并验证并发或重复请求不会绕过单活动任务约束。
12. 覆盖成功提交后自动切换报告记录并打开新任务；刷新、重新进入和直接链接都只读，不重新提交任务。
13. 覆盖补全内容、生成单条总结、汇总报告、完成四种阶段表达，以及总数、待处理、处理中、新总结、复用和失败数量与持久状态一致。
14. 覆盖取消、登录、安全验证、显式继续、配置阻塞、中断、个别条目失败、报告失败重试和无相关内容，确保正常结果与故障具有不同文案和可用操作。
15. 覆盖完成报告在报告记录中直接阅读，来源和覆盖可追溯，报告重试不重新运行成功的补全与单条总结。
16. 覆盖旧报告进入统一列表、旧单条处理历史进入内容详情，并确认页面改造不删除或改写历史正文、总结、来源及报告。
17. 覆盖键盘焦点：进入页签、打开与关闭 Sheet、打开与关闭 Dialog、翻页及返回表格行；活动状态和异步错误通过语义化状态区域通知辅助技术。
18. 现有报告页面路由测试、报告选材组件测试、报告生成客户端契约测试、全库选材业务测试和报告生成集成测试作为优先扩展的既有先例；只有固定批量快照、报告名称和单活动任务约束确实无法在现有边界表达时才增加新的高层业务测试入口。

## Out of Scope

- 不改造舆情爬取页面、采集规则、平台账号或浏览器登录流程。
- 不新增采集到报告的一键自动编排；该能力继续属于自动任务范围。
- 不在报告生成页面管理自动分析授权、模型连接、媒体保留或容量策略。
- 不增加内容筛选、全文搜索、自定义排序、可配置列、列拖拽或用户保存视图。
- 不增加报告时间范围、汇报对象、报告格式模板或审批流程。
- 不实现多份手动报告并发或排队。
- 不为大批量选材设定新的业务条数上限，也不承诺无限模型或平台处理能力。
- 不改变平台补全、图片理解、视频理解、总结复用、相关性判断或报告生成算法。
- 不删除旧报告、旧单条总结、旧处理尝试或历史来源。
- 不访问小红书、不购买第三方服务，也不以此次页面改造扩大真实微博验收范围。
- 不在本规格阶段编写实现代码、迁移日常数据库、触发真实平台请求或调用付费模型。

## Further Notes

- 本规格遵循项目领域词汇：“舆情内容库”“报告选材”“待分析条目”“分析失败条目”“未完成分析条目”“单条总结”和“报告生成”具有独立含义，不能退回“初步分析”或笼统“未分析”等旧称谓。
- 本规格落实 ADR-0008：舆情爬取独立入库，手动报告从内容库选材后才启动；自动化另行管理。
- Shadcn Data Table 是由表格原语和表格状态管理组合出的模式，不是单个可安装组件。当前项目已具备主要 Shadcn 视觉原语；若实现需要高级表格状态，可增加 TanStack Table 作为页面层依赖。
- 当前系统已经拥有报告生成、进度、取消、人工恢复、总结复用、报告重试和历史读取能力。本规格应优先重组这些能力，不复制第二套任务引擎。
- 当前服务端的全库策略在创建任务时求值；新设计要求批量按钮只形成点击当时的可见固定集合，因此实现必须把“形成选材快照”和“创建报告任务”拆开。
- 当前报告生成意图没有用户命名字段，且允许多份任务进入串行处理；报告名称和单活动任务准入需要持久契约与兼容迁移。
- 讨论过程及可逆界面细节保存在同一采集与报告重设计工作区的页面设计记录中；该记录是本规格的来源，不替代本规格的验收边界。
- 规格已发布到本地 Markdown 任务跟踪目录并标记 `ready-for-agent`。发布规格不代表开始实现。
