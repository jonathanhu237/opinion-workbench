# 媒体缓存完整退出与小规模自动任务真实验收

## Problem Statement

当前版本已限定为原帖文字理解，新内容补全不再下载图片或视频，但设置页面仍显示媒体缓存，后台仍启动保留策略清理，历史详情仍暴露本地媒体回看入口。这些遗留能力让使用者误以为媒体仍参与当前分析，也增加了维护成本。正文资料读取与缓存服务还有耦合，直接删除缓存对象可能破坏文字复用及报告生成。

自动任务虽有代码测试，但尚未找到真实“计划触发、舆情爬取、内容补全、单条总结、舆情报告”串联验收证据。手动采集与报告成功不能证明自动任务已可用。使用者希望快速完成小规模真实验证，不希望再次采集大量内容或反复扩大测试。

## Solution

从当前产品完整退出媒体缓存：移除设置、下载和保留策略、后台清理、本地媒体读取及历史媒体回看能力；删除本项目管理的已有媒体文件。保留原帖文字、来源信息、舆情内容库、单条总结、舆情报告及处理记录，使纯文字工作流独立运行。

使用本机浏览器、当前真实模型配置，创建小规模验收自动任务：仅微博、仅关键词“龙田街道”，每次最多2条。分别验证一次立即运行和一次真实计划时间触发。定时验证完成后停用任务。若后一次没有新增命中，则核验正确结束，不为凑报告扩大采集。

## User Stories

1. 作为使用者，我希望设置中不再出现媒体缓存配置，以便界面与当前文字理解范围一致。
2. 作为使用者，我希望不再配置媒体期限和容量，以便减少无实际用途的设置。
3. 作为使用者，我希望应用不再下载图片或视频，以便避免无用的网络和存储开销。
4. 作为使用者，我希望后台不再启动媒体保留策略任务，以便应用只运行需要的服务。
5. 作为使用者，我希望已有媒体文件也删除，以便完整退出该能力。
6. 作为使用者，我希望没有媒体文件时也能正常完成退出，以便空缓存不导致错误。
7. 作为使用者，我希望清理仅作用于本项目管理的媒体文件，以便不误删其他应用或个人文件。
8. 作为使用者，我希望正文和来源信息保留，以便继续核对原帖文字。
9. 作为使用者，我希望已有单条总结与报告保留，以便历史成果不会因媒体功能退出丢失。
10. 作为使用者，我希望处理记录和历史引用保持可读，以便仍可追溯分析过程。
11. 作为使用者，我希望内容详情不再显示失效的本地图片、视频或检查媒体按钮，以便不会进入不可用操作。
12. 作为使用者，我希望原帖链接继续可用，以便需要图片或视频信息时自行查看原帖。
13. 作为使用者，我希望已有文字资料能继续复用，以便报告生成不依赖已退出的缓存服务。
14. 作为使用者，我希望文字不足时继续得到待人工核查条目，以便不会把未理解的媒体内容误判为无关。
15. 作为使用者，我希望旧的媒体设置链接有合理去向，以便历史收藏不会导致页面崩溃。
16. 作为使用者，我希望升级及再次启动不会恢复媒体功能或反复报错，以便退出稳定有效。
17. 作为自动任务管理者，我希望使用一个平台和一个关键词验证，以便控制时间和采集量。
18. 作为自动任务管理者，我希望每次最多采集2条，以便验证不会扩展为大规模采集。
19. 作为自动任务管理者，我希望实际点击立即运行并看到真实结果，以便确认人工触发链路可用。
20. 作为自动任务管理者，我希望等待真实计划时间触发，以便确认调度器确实驱动任务运行。
21. 作为自动任务管理者，我希望有新增且可处理材料时自动进入单条总结和报告，以便验收覆盖真实模型调用。
22. 作为自动任务管理者，我希望无新增命中时任务正确结束，以便不会为了出报告重复扩大采集。
23. 作为自动任务管理者，我希望计划触发不产生重复运行，以便避免重复采集和模型费用。
24. 作为自动任务管理者，我希望浏览器未启动时有可理解的启动或失败结果，以便不会出现无提示的卡住状态。
25. 作为自动任务管理者，我希望登录或安全验证障碍明确暂停，处理后显式继续，以便保留人工恢复边界。
26. 作为自动任务管理者，我希望阶段失败显示实际原因，以便知道验收是否完成及失败在哪里。
27. 作为自动任务管理者，我希望定时验收一次后停用，以便不会继续自动采集。
28. 作为使用者，我希望保留验收运行与报告的关联证据，以便区分真实运行和模拟测试。
29. 作为使用者，我希望验收沿用本机登录态和当前模型配置，以便不重复配置环境。
30. 作为使用者，我希望最终明确看到哪些行为已验证、哪些仅由受控测试覆盖，以便不会把有限验收误当成全面稳定性保证。

## Implementation Decisions

- 完整退出当前应用的媒体缓存能力，覆盖设置展示、本地媒体读取接口、下载及缓存服务、保留策略调度、历史媒体展示和相关运行时装配。旧媒体设置地址可归到设置页，不再展示媒体区域。
- 将保存正文资料的读取从媒体缓存服务中解耦，复用现有内容资料仓储；退出缓存不改变文字资料的保存和复用语义。
- 历史记录中的媒体元数据不得再触发下载或本地文件读取。保留历史总结、报告、来源及处理记录；允许其作为历史事实说明当时输入，不承诺本地媒体仍可回看。
- 删除本项目管理的已有媒体文件，包括可识别的历史媒体副本；不得借此删除整个运行目录、数据库备份、截图、日志、密钥、登录资料或其他非媒体数据。先列明受管媒体存储位置，按实际存在情况清理；不存在视为正常。删除失败应可见，不得宣称已全部删除。
- 数据库如需升级，采用现有迁移机制，保证旧库可升级和重复启动幂等；不为代码整洁而重建业务数据库或抹掉历史记录。具体删表与保留历史元数据方案由实施时依赖核查决定。
- 所有开发、应用服务、SQLite、浏览器与真实验收均在本机运行。
- 验收使用单一微博平台、单一“龙田街道”搜索词，每词采集上限2条。两次运行发现条目上限合计4条，去重后可能更少；不得偷偷提升上限、增加搜索词、扩展平台或全库分析。
- 使用独立命名的验收自动任务和监控规则，避免改变用户现有任务或规则。沿用当前真实模型配置和已有登录态。
- 一次立即运行，一次真实计划时间触发。计划时间设置为方便现场短时间等待的最近合法时间，使用明确的本地时区；到期时保持本机应用服务运行。
- 定时运行一经产生即停用后续调度，确保仅一次计划触发；最终核实停用状态。保留已产生运行记录，不通过删除记录伪装没有重复触发。
- 无新增命中时依照现有自动任务语义结束，不伪造新来源或强制重做历史总结。若两次都无新增，真实模型与报告串联应明确记为未覆盖，不虚报全链路通过。
- 当前自动任务直接进入采集批次，浏览器可用性是待验证风险。该风险不等于已经证明存在缺陷；若阻止本次验收，应修复所需启动或错误反馈，并保留全局浏览器操作互斥。
- 人工登录或安全验证继续遵守显式“继续采集”，不得自动绕过。仅修复退出媒体能力或完成本次小规模验收所必需的问题。
- 本决定延续原帖文字理解范围，进一步取消旧媒体保留策略及历史本地媒体回看承诺。实施时同步领域词汇与相关架构决策，注明本次用户明确授权删除已有媒体，不能将此前“历史媒体不自动清理”的决定继续当作当前要求。

## Testing Decisions

- 首选最高层的现有应用/API边界，用用户可观察的入口、响应、持久运行状态及报告结果判断成功；不写仅验证内部函数调用或CSS类名的测试，不为本任务引入新的生产测试接口。
- 复用现有自动任务应用/API测试、报告生成测试和媒体相关接口测试基础设施。受控测试使用外部依赖替身覆盖异常；其结果不能代替真实验收。
- 媒体退出的核心回归：从含历史媒体引用和已保存文字资料的旧库启动，完成升级，确认文字可读且可继续生成报告；原帖链接、历史报告和处理记录仍可访问，本地媒体入口退出且不产生媒体请求。
- 清理边界验证：受管媒体被删除，空目录及再次执行正常；同目录中的非媒体资料、数据库、密钥、登录资料不被清理。包含读取历史记录不会重新创建媒体缓存的验证。
- 前端使用既有设置和详情路由测试核验入口退出和兼容跳转；结合本机页面检查，确认没有残留的媒体操作和失效展示。
- 自动任务受控测试覆盖浏览器未启动、浏览器占用、人工验证暂停及显式恢复、阶段失败、计划触发去重和任务停用。复用已有服务/API边界，不主动制造真实平台风控。
- 真实立即运行记录任务ID、运行ID、触发方式、采集数量、阶段状态和报告关联；若存在新增且可处理材料，应由真实模型产出总结和报告，并实际打开阅读。
- 真实定时验证必须等待实际时钟到期，记录计划时间、实际触发时间及运行ID；直接调用调度器或构造数据库记录不算通过。
- 第二次重复发现导致无新增时，验收正确的终态及无多余分析/报告行为；明确该次未重复覆盖模型产出。
- 真体验收总预算为两次小规模采集。失败优先用已有材料和受控测试定位；需要额外真实采集时明确报告原因，不自动进入无限重试。
- 最终记录实际采集量、真实模型调用是否发生、报告是否完成、定时任务是否停用，以及未覆盖项。运行“成功”标签本身不替代产物核对。
- 用户已确认测试边界：应用/API结果加两次小规模真实运行，浏览器关闭、人工验证等异常场景使用受控测试，复用现有测试且不扩大真实采集。

## Out of Scope

- 恢复图片、视频、音轨理解，或新增OCR、语音转写。
- 跨五平台的完整自动任务矩阵、大规模抓取、长时间稳定性或压力测试。
- 关闭应用后的系统级调度、休眠唤醒、常驻守护进程等新能力；本次真实定时验收以本机服务运行中为前提。
- 重写自动任务体系、改变新增命中与重复命中处理策略、全库重跑、修改报告提示词。
- 删除业务数据库或用户其他数据，重置模型配置、登录态或现有任务。
- 因本任务处理所有既有测试失败，或上传、部署到Centaurus。
- 报告页面加宽的进一步设计：该调整已完成，本规格不重复实施。
