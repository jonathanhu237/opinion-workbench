# 报告记录页面优化讨论

Status: discussion-complete

## 当前结论速览

- 导航只保留一级“舆情报告”，默认进入全部报告记录的 Data Table。
- “生成报告”是列表工具栏操作，打开同一个三步弹窗：选择内容 → 内容分析提示词 → 报告总结提示词；报告名称、模型等其余设置位于第三步，两套提示词保留默认值。
- 成功提交后关闭弹窗，表格行展示紧凑进度；详细进度和人工处理按需打开侧边抽屉，不设常驻大进度面板。
- “查看报告”进入列表的下一层独立全宽详情，查看正文及按需展开的来源、逐条处理结果；不是新的左侧菜单，返回保留列表位置。
- 本轮界面方案已讨论完成。执行、失败重试和草稿保存范围沿用现有规则；规格已按后续 to-spec 请求发布至同目录 spec.md，尚未授权实现。
- 下文保留讨论演变；有冲突时以第四轮及以后最新确认结果、上述速览为准。

## 已确认的目标与既有约束

- 用户反馈报告记录页面混乱，要求使用 grill-with-docs 讨论优化方案。
- 本轮处于设计讨论阶段，尚未授权按新方案实现。
- 沿用 CONTEXT.md：报告记录覆盖进行、暂停、失败和完成等状态；舆情报告指完成后的可阅读产物。
- 保留用户此前确认的简洁页面标题和紧凑刷新操作要求。
- 页面呈现调整不等于删除历史数据。

## 现状依据

- `frontend/src/routes/report-generations.tsx`：默认选择活动或最新记录；选中记录详情置于报告列表之前，选中后列表默认折叠。
- `frontend/src/routes/results.tsx`：报告记录页在报告主体之后常驻 `ResultsJobs` 区域，旧单条处理任务仍进入主视图。
- `frontend/src/routes/report-generations.tsx`：生成阶段、说明、处理数量、来源处理结果、报告覆盖和报告正文纵向堆叠。
- 最近的刷新按钮调整增加了与统一页头同名的“报告记录”卡片标题，与既有导航精简规格关于避免重复标题的要求冲突。

## 第一轮建议（已被用户调整）

1. 普通导航进入时先展示报告表格，点击记录进入全宽详情；提交成功和已有深链仍直接打开指定记录。此建议将替代旧报告页面规格中的默认自动打开活动/最新记录行为。
2. 详情按状态确定重点：进行中突出当前进度与必要操作，完成后突出报告正文；来源、逐条处理结果和调用详情按需展开。
3. 从报告记录主页移除常驻旧单条处理任务区，历史尝试从内容详情或兼容链接进入，不删除数据。

这些是第一轮建议，不作为已确认决定；其中将进度放在报告记录详情中的建议被以下用户指示替代。

## 用户此前明确的页面分工（被第四轮单页方案替代）

- 报告记录页面只展示所有报告记录。
- 当前报告生成进度应放在“生成报告”页面顶部。
- 据此撤回先前将当前进度和处理操作集中于报告记录详情的建议。
- 该分工将修改旧报告页面规格 Implementation Decisions 20–23，以及导航规格 Implementation Decisions 14–17 中关于提交后跳转、进度及恢复操作归属的界面决定。ADR-0008 的采集入库与手动选材生成报告分开原则仍然适用。

## 第二轮当时已确认（Q4–Q5；页面归属被第四轮方案替代）

- 提交成功后留在生成报告页，顶部显示当前任务的阶段、已处理数量，以及暂停时的必要操作；没有当前工作时不保留空进度容器。下方仍为内容库及选材。
- 报告记录使用表格，打开已完成记录后阅读报告正文和按需查看来源，不常驻当前任务进度或独立旧单条任务区。
- 报告记录包含进行中、失败、取消和完成等所有状态；在列表仅显示简洁状态，进行中手动记录通过“查看进度”进入生成报告页。
- 完成后不自动跳转；生成报告页顶部转为完成提示、处理成功及失败数量和“查看报告”入口，由用户决定何时打开。

## 第三轮待确认

- Q6：表格展示报告名称、生成方式（手动/自动）、状态、创建时间、选材数量和操作；最新优先、分页读取，刷新放在表格工具栏，首版不增加筛选或统计卡片。
- Q7：点击“查看报告”进入全宽阅读详情，默认展示正文；来源与逐条处理结果按需查看；返回列表保留分页位置。
- Q8：生成报告页顶部使用紧凑任务区，常驻任务名称、当前阶段和已处理/总数，展开后查看详细数量与失败条目；刷新或切页返回仍能恢复当前进度。
- Q9：手动和自动报告均进入同一记录表格；手动报告进度在生成报告页，自动报告进度保留在对应自动任务运行详情。报告重试结果保留与原记录的关联及历史，具体阅读与重试操作在前置决定明确后继续收敛。

以上第三轮内容为建议，尚未确认。

## 第四轮：用户提出单页报告入口（当前方向）

- 左侧“舆情报告”不再分两层，直接进入一个以报告为中心的页面；取消“生成报告”和“报告记录”两个二级入口。
- 页面主体仅展示所有报告记录的 Data Table，生成报告是页面上的操作按钮，不再是独立导航页面。
- 点击“生成报告”打开窗口，窗口内展示已采集的内容，支持逐条选材及“选中全部未分析内容”，随后发起生成。
- 本轮为方案讨论，不修改应用代码。
- 上述方向替代第二轮关于两个页面及提交后停留在独立生成报告页的决定。第三轮 Q8–Q9 中依赖独立生成报告页的建议也不再适用；其他第三轮建议尚未获确认。
- 领域含义不变：选材仍来自已有舆情内容库，“未分析条目”仍指尚无可用成功总结的内容；此处页面名“舆情报告”不意味着仅保留成功报告或删除其他状态的历史记录。

### 第四轮原建议（确认结果见第五轮）

- Q10：同一个大弹窗内分为“选择内容 → 生成设置”两步；第二步沿用报告名称、模型和上下两套带默认值的提示词等现有设置，允许返回修改选材，不叠加第二个弹窗。两步拆分是针对本项目表格与长设置表单的设计建议；参考 ui-ux-pro-max 已核实的多步进度及提交反馈指南，明确标示步骤和提交结果。
- Q11：成功提交后关闭弹窗，在报告表格新增记录；记录行显示紧凑阶段/数量，点击查看详细进度及必要的人工处理操作。完成后该行提供“查看报告”。关闭窗口、切页不停止后台任务；不再另外常驻一个大进度区域。

Q10 的两步建议被第五轮用户指定的三步替代；Q11 在第五轮获确认。

## 第五轮已确认：三步生成弹窗与行内进度

- 用户指定同一弹窗分三步：第一步选择内容；第二步填写分析提示词；第三步填写总结提示词。这里“分析提示词”用于逐条内容的理解/单条总结，“总结提示词”用于将所选内容的理解汇总为整份报告，不更改已有业务处理顺序。
- 第二、三步分别呈现原有两套提示词，不再上下同时展示；此前默认提示词的要求仍适用。
- 用户对 Q11 回复“我没意见”：成功提交后关闭生成弹窗，在报告表格中新增记录；行内显示紧凑阶段及数量，按需查看详细进度和人工处理操作；完成后提供“查看报告”。关闭弹窗或切页不停止后台工作；不另设常驻大进度区。
- 第四轮中“未分析条目”范围及其他已确认业务规则不变。

## 第六轮已确认（Q12–Q14，用户回复“我没意见”）

- Q12：报告名称及模型等其余生成设置统一放在第三步；两套提示词预填现有默认值，提供恢复默认；前后切换保留已选内容与输入，仅第三步的“开始生成”提交任务。
- Q13：报告列表使用报告名称、生成方式、状态/进度、创建时间、选材数量、操作六列；手动和自动生成均列入，覆盖所有状态，最新优先并分页。刷新与生成按钮同在表格工具栏，首版不加筛选或统计卡片。
- Q14：详细进度与人工处理操作使用按需打开的侧边抽屉；自动报告保留跳转对应自动任务运行详情的入口。已完成报告使用全宽阅读视图（不是新的菜单项），来源和逐条处理结果默认收起，返回保留原列表分页位置。

- 用户进一步明确：“查看报告就会进入到下一层，就能看到更详细的内容。”因此查看报告进入报告列表下一级的独立全宽详情视图，不是在表格内展开正文，也不是用生成弹窗或侧边抽屉阅读报告。左侧导航仍只有“舆情报告”一个入口，详情提供返回报告列表的路径。
- Q6 的列表字段、Q7 的阅读方式及 Q9 的手动/自动报告归集，已由本轮 Q13–Q14 的确认收敛；旧版依赖独立生成报告页的进度跳转不再保留为产品设计。
- 三步弹窗、列表内容、详情层级已达成一致。未提交关闭、失败重试与原有历史入口的检查结果如下；本轮不新增与页面改版无关的业务能力。

## 已核实的继承边界（维持原有能力，不另开功能分支）

- 普通未提交弹窗关闭仅隐藏，同次页面挂载重新打开仍保留选材和表单；选材原有 sessionStorage 恢复能力保留，普通名称及提示词不新增跨刷新/卸载草稿持久化。
- 已经提交但响应不确定的固定请求持久化和防重复提交机制保留，不能在弹窗关闭或步骤切换时当成普通草稿清除。
- 单条分析失败仍可选入新报告，批量“全部未分析”仍包含此类条目；已有成功总结继续复用，失败历史不覆盖。
- “仅重试报告”继续复制原报告冻结来源及已有证据，只重跑报告汇总，不重新补全或重跑单条分析。重试产生关联原报告的新记录，不覆盖旧记录；新记录自然进入已确认的统一列表，应用同样的行内进度和详情入口，不引入自动跳转的新规则。
- 取消/中断的手动生成仍需重新选材启动新任务，已成功总结可复用；不借此次改版新增原地恢复/重试能力。
- 历史记录和已有链接目标保留；路由兼容属于实现要求，不保留已废弃的两级左侧导航、常驻旧单条任务区或两套平行的报告列表。
- 依据：`frontend/src/routes/report-selection-actions.tsx`、`frontend/src/routes/results.tsx`、`frontend/src/routes/report-generations.tsx`、`backend/src/longtian_api/repositories/topic_reports.py`，已由只读核查确认。

- 这次是可逆的界面组织调整，不新建 ADR；领域术语含义不变，不把 UI 细节写入 CONTEXT.md。
