# 舆情报告单页列表与三步生成流程

Status: open

Labels: ready-for-agent

## Problem Statement

使用者希望进入“舆情报告”后直接看到所有报告，需要生成时再选材，而不是先理解“生成报告”和“报告记录”两个导航入口的区别。当前页面把活动任务、生成阶段、数量统计、来源处理结果、报告正文和旧单条处理任务上下堆叠；默认打开活动或最新记录又将报告列表压在详情之下，因此报告难以浏览，任务与产物也难以区分。

现有内容表格和选材操作常驻独立页面，生成设置再进入弹窗。使用者最终确认的流程是：以报告 Data Table 为唯一主页，通过同一个三步弹窗选择内容、填写分析提示词、填写总结提示词；提交后在对应报告行看进度，点击“查看报告”才进入下一层详情。此前“进度放在独立生成报告页顶部”的中间方案已经撤回。

改版必须保持真实业务能力：手动、自动、重试和历史报告都能找到；活动、暂停、失败等记录不能因没有成功正文而消失；选材、失败重试、显式人工继续与提交防重不能因为调整页面而改变。

## Solution

左侧只保留一个可直接点击的“舆情报告”入口，不再展开“生成报告”和“报告记录”两个子菜单。主页只放紧凑工具栏和报告 Data Table：工具栏并排提供刷新和“生成报告”，表格列出报告名称、生成方式、状态/进度、创建时间、选材数量和操作。报告最新优先、统一分页，不默认打开任何记录，不增加统计卡片或筛选。

点击“生成报告”打开一个大弹窗，按以下顺序完成准备：

1. **选择内容**：浏览已有舆情内容库，逐条或跨页勾选，也可点击“选中全部未分析内容”。选材不启动采集或分析。
2. **内容分析**：填写用于单条总结的分析提示词，预填现有默认值并可恢复默认。
3. **报告总结**：填写用于整份报告的总结提示词，确认报告名称、当前模型及选材范围，最后点击“开始生成”。

步骤切换保留输入，不层叠第二个生成弹窗。成功提交后关闭弹窗并留在报告列表，新记录立即可见；表格行展示紧凑阶段及真实数量，详细进度、失败原因和必要的人工操作按需在侧边抽屉查看。任务完成时不自动跳转。

点击“查看报告”进入报告列表的下一层独立全宽详情，默认以报告正文为主，来源和逐条处理结果按需展开。详情不是新的左侧菜单，也不是表格内展开或阅读弹窗；返回后恢复原列表位置。

## User Stories

1. 作为舆情分析人员，我希望左侧只有一个“舆情报告”入口，以便不必先判断应该进入生成页还是记录页。
2. 作为舆情分析人员，我希望点击该入口直接打开报告列表，以便立即看到已有工作和成果。
3. 作为舆情分析人员，我希望主页以 Data Table 展示报告，以便快速扫描和比较多份记录。
4. 作为舆情分析人员，我希望进入列表时不自动展开最新或活动记录，以便阅读顺序由我决定。
5. 作为舆情分析人员，我希望刷新和“生成报告”在同一个紧凑工具栏，以便按钮不会各占一行。
6. 作为舆情分析人员，我希望页面没有重复标题、冗长副标题、统计卡片和常驻旧单条任务区，以便首屏聚焦报告。
7. 作为舆情分析人员，我希望手动、自动和历史报告出现在同一张表，以便不必在两套列表中寻找。
8. 作为舆情分析人员，我希望等待、进行、暂停、失败、取消、中断、空结果和完成的记录都能找到，以便不会遗漏未成功的工作。
9. 作为舆情分析人员，我希望从报告名称、生成方式、状态、创建时间和选材数量辨认记录，以便快速定位目标。
10. 作为舆情分析人员，我希望报告按最新优先分页展示，以便数据增多后仍能正常浏览。
11. 作为舆情分析人员，我希望同一次手动生成及其最终报告只出现一行，以便不会把同一工作误认为两份报告。
12. 作为舆情分析人员，我希望重试产生的新报告单独保留并关联原记录，以便追溯失败与重试历史。
13. 作为舆情分析人员，我希望不同记录类型跨页时不重复、不遗漏，以便“所有报告”确实覆盖全部记录。
14. 作为舆情分析人员，我希望列表读取失败时看到明确提示并能重试，以便不会将服务异常误认为没有报告。
15. 作为舆情分析人员，我希望无报告时仍能点击“生成报告”，以便知道如何开始。
16. 作为舆情分析人员，我希望点击“生成报告”才打开选材窗口，以便内容库不长期挤占报告主页。
17. 作为舆情分析人员，我希望弹窗清楚标示三个步骤，以便知道当前位置和剩余操作。
18. 作为舆情分析人员，我希望第一步展示历次采集积累的内容，而不只展示最新批次，以便自由选择报告来源。
19. 作为舆情分析人员，我希望能逐条勾选并跨页保留选择，以便组合不同批次的内容。
20. 作为舆情分析人员，我希望表头全选只作用于当前页，以便不会误选未查看的内容。
21. 作为舆情分析人员，我希望“选中全部未分析内容”覆盖全库符合条件的条目，以便一次选中积压内容。
22. 作为舆情分析人员，我希望未分析内容包含没有成功总结的历史失败条目，以便不用再选择“是否包含失败”。
23. 作为舆情分析人员，我希望批量选材加入已有手选集合并去重，以便不会丢掉此前的选择。
24. 作为舆情分析人员，我希望选材在操作时固定为明确条目，以便后来入库的内容不会悄悄加入本次报告。
25. 作为舆情分析人员，我希望批量选择后仍能取消任意条目或清空选择，以便控制实际范围。
26. 作为舆情分析人员，我希望随时看见已选数量，以便翻页和步骤切换后仍清楚选材规模。
27. 作为舆情分析人员，我希望查看内容的正文、素材和既有处理信息后能回到选材，以便核实来源又不丢失输入。
28. 作为舆情分析人员，我希望处理中的条目不能被重复提交，以便避免重复分析和资源争用。
29. 作为舆情分析人员，我希望选择内容、查看详情和点击下一步都不会启动分析，以便只有明确提交才产生任务。
30. 作为舆情分析人员，我希望第二步只重点处理分析提示词，以便专注决定每条内容应如何理解。
31. 作为舆情分析人员，我希望第三步重点处理总结提示词，以便专注决定最终报告如何组织和表达。
32. 作为舆情分析人员，我希望两套提示词均有现有默认值和恢复默认操作，以便不必从空白开始。
33. 作为舆情分析人员，我希望临时修改提示词只作用于本次生成，以便不会修改全局默认规则。
34. 作为舆情分析人员，我希望已有成功总结继续复用且有简短说明，以便不会误以为修改提示词会重跑全部条目。
35. 作为舆情分析人员，我希望报告名称在第三步预填且可修改，以便普通报告能快速提交、专题报告也容易辨认。
36. 作为舆情分析人员，我希望第三步能确认当前使用的模型并找到设置入口，以便了解本次调用对象。
37. 作为舆情分析人员，我希望提交前知道选中总数、需要分析、复用总结和失败重试的数量，以便了解真实处理规模。
38. 作为舆情分析人员，我希望上一步和下一步不会清空选择或提示词，以便反复调整不必重填。
39. 作为舆情分析人员，我希望普通关闭弹窗后在同一页面重新打开仍能继续填写，以便不会因临时收起而丢掉准备工作。
40. 作为舆情分析人员，我希望无选材、提示词无效、模型缺失或选材状态无法确认时不能提交，以便不会创建必然无效的工作。
41. 作为舆情分析人员，我希望当前已有活动报告时仍能准备下一份选材，但不能绕过现有提交限制，以便等待期间可以继续准备。
42. 作为舆情分析人员，我希望只有最后一步的“开始生成”提交任务，以便不会在前两步误启动。
43. 作为舆情分析人员，我希望提交失败保留输入，响应不确定时重试原请求而不重复创建，以便安全恢复网络问题。
44. 作为舆情分析人员，我希望成功提交后关闭弹窗并立即看到新记录，以便确认工作已经被接收。
45. 作为舆情分析人员，我希望提交及生成完成后都不会强制进入报告详情，以便浏览列表或准备下一份工作不被打断。

54. 作为舆情分析人员，我希望点击“查看报告”进入下一层独立详情，以便获得足够空间阅读正文。

## Implementation Decisions

### 导航、列表与记录归集

1. 修改应用导航和报告区域的路由组织：“舆情报告”从展开分组改为直接进入报告列表的普通一级链接；删除其两个二级菜单。保持其他导航的顺序和行为不变，应用首页仍进入平台账号，设置仍是单层入口。
2. 报告列表与报告详情拥有可直接访问的稳定地址。详情属于报告区域的下一层视图，不新增左侧菜单。浏览器刷新、前进、后退及直接访问均可还原目标，导航仍明确处于“舆情报告”区域。
3. 列表主页仅保留唯一页面标题、工具栏、表格、分页和必要状态反馈。删除与统一页头重复的卡片标题、冗长页面级说明、常驻选材栏、旧单条处理任务区及纵向报告详情；不删除字段帮助、错误、空状态和必要风险提示。
4. 刷新与“生成报告”放同一个工具栏，不增加单按钮整行容器或横跨侧边栏的固定底栏。普通导航不自动打开活动、最新或第一条报告；无活动任务时不存在空进度容器。
5. 报告表格使用项目现有 Shadcn 风格的表格、按钮和分页组件体系。固定信息列为报告名称、生成方式、状态/进度、创建时间、选材数量、操作；首版不增加筛选、搜索、统计卡片、列管理或用户自定义排序。采用最新创建优先的稳定排序，沿用二十条的分页规模。
6. 为报告列表形成统一的只读记录视图，包含手动报告生成、自动/独立历史报告以及报告重试。手动生成及其关联的最终报告表示同一次工作，只占一行；独立重试表示新工作，必须保留单独一行及父报告关系。去重依据真实关联而非名称、创建时间或当前页是否碰巧同时出现。
7. 统一记录标识必须区分来源类型与原始身份，不能把不同表中的相同数字标识视为同一记录。展示所需信息包括稳定身份、名称或确定性回退名称、生成方式、创建时间、选材总数、真实状态/阶段、可用进度数量、对应详情/操作目标，以及可用的自动任务和父报告关联。
8. 手动/自动按真实业务来源归类，不因现有展示代码把自动报告当作“旧报告”而误标。重试继承原报告的生成来源，并可在详情说明重试关系；确实缺少历史来源或名称时使用明确的历史回退展示，不伪造关联。旧的区间/独立报告同样保留可见性。
9. 全部来源必须使用一个排序和分页体系。仅拼接两种记录各自的当前页再做页内去重不满足要求；禁止为了展示一页先读完全部历史，也不能要求用户分别翻两套分页。优先复用现有读取能力；若不足以保证全局归集、排除重复及稳定分页，允许增加最小的后端只读列表查询，并保留原有读取和执行契约。此处不新增报告执行引擎或持久化任务模型。
10. 列表读取保持有界，不为每一行预先加载完整正文、全部来源和全部处理尝试。详情及长来源列表按需读取和分页；后端如增加列表查询，应返回列表实际需要的摘要及身份关联。
11. 普通轮询和手动刷新不重置正在浏览的历史分页、不自动展开记录。成功创建本次报告时回到最新一页以使新记录可见，但不进入详情或自动打开进度抽屉。刷新失败保留可用旧数据并显式提示，不能把未成功读取的部分假装成完整列表。

### 三步生成弹窗

12. 报告主页的“生成报告”首先是打开准备流程，不直接提交。没有预选条目、尚未配置模型或存在活动报告时仍可打开并浏览、准备选材；提交限制在相应步骤就近解释，不用禁用整个入口来阻止准备工作。
13. 复用现有内容库、报告选材和生成确认能力，组织成一个三步弹窗。步骤固定为“选择内容”“内容分析”“报告总结”；步骤标识始终可辨认。前两步使用“下一步”，后两步支持“上一步”，只有第三步显示最终“开始生成”。不得用弹窗套另一个生成弹窗实现步骤。
14. 第一步使用已有内容 Data Table 和既有内容摘要、素材、时间、处理状态及详情能力，按最新入库优先、每页二十条呈现。逐条选择跨页保留，表头全选只影响当前页；处理中条目保持不可重复选择。已有成功总结仍可被手动选入并复用。
15. “选中全部未分析内容”调用现有全库资格与快照能力，选择尚无可用成功总结的内容，统一涵盖待分析及分析失败条目，不增加“包含失败”开关。批量结果与已有手选条目合并去重，允许逐条移除；不局限当前页、不截断为某个任意数量、不自动吸收后来入库的内容。
16. 全部步骤使用同一明确选材集合，并保持已选总数可见。第一步提供清空和修改选择的能力；第三步核对总数、待分析、已有总结与失败重试数量。没有条目时不能进入有效生成流程；预览失败或与当前选材不匹配时不能最终提交，并提供重新检查入口。
17. 第二步的“分析提示词”映射现有单条总结提示词，第三步的“总结提示词”映射现有报告汇总提示词。两者各自预填默认内容、可修改和恢复默认，覆盖只对本次请求生效；切换步骤不保存全局设置。已有可用总结继续复用，修改分析提示词不变成强制重跑已总结条目的功能。
18. 第三步集中报告名称和模型区域。名称沿用带日期的默认值、允许修改并继承现有长度校验。当前实现只有全局保存的一套模型配置，因此本次保留只读展示当前模型、缺失/无效提示以及前往设置的入口；不假设已经存在按报告切换模型或模型列表，也不从弹窗静默改写全局配置。该项是基于当前能力对讨论中“模型选择”的保守技术澄清，不新增模型管理。
19. 第三步保留简洁的正文/必要媒体发送及模型用量提示、选材预览、字段校验和配置冲突指导。沿用现有配置版本校验，不能让用户确认旧模型信息后静默改用新配置。
20. 前后切换与同次页面挂载内关闭重开保留普通表单输入。选材沿用会话级恢复能力；普通报告名称和提示词不新增跨刷新、跨页面卸载或长期草稿存储。已提交但响应不确定的请求不属于普通草稿，必须继续按既有固定请求持久化和恢复规则处理。
21. 只有最终提交启动报告生成；选材、下一步、打开详情、读取预览、刷新和进入页面均不得启动采集、补全或模型调用。实际处理仍按必要补全、单条总结/复用、报告汇总顺序执行，三个表单步骤不是新增的三个后台业务阶段。
22. 沿用现有活动任务准入限制，不新增并发、排队或自动启动下一份报告。可准备下一份选材，但活动任务结束前不能绕过服务端限制提交；失败、配置变更和内容处理中等冲突要保留输入并说明原因。
23. 创建期间禁止重复提交，沿用既有提交锁定及响应不确定时重放同一固定请求的行为。步骤切换、重开弹窗或刷新不能生成另一个请求身份绕过防重，也不能把原请求的冻结选材替换为新草稿。确认创建成功后才清除本次已提交草稿、重置普通表单、关闭弹窗并更新列表。

### 行内进度、异常处理与重试

24. 进度以既有持久化状态和计数为事实来源，不新增前端模拟进度状态机或估计百分比。行内紧凑展示如“正在总结 · 已处理 30/50 · 失败 2”；已处理可包含已成功、复用及已结束的失败条目，失败数量必须单独说明，不能伪装成成功。单条处理结束但报告仍在汇总时不能显示整份报告已完成。
25. 针对不同记录来源展示实际可得的阶段与数量。只有报告汇总阶段信息的独立/重试报告不得伪造补全或单条总结进度；缺少历史数量时明确显示未知，而不是填零或编造精确进度。
26. “查看进度”按需打开侧边抽屉，展示当前记录身份、阶段、详细计数、处理结果及合法的恢复操作。失败、配置阻塞、取消和中断记录也能打开状态详情，不因没有正文而失去检查入口。切换记录时不得混入上一记录的详情、来源分页或控制版本。
27. 取消、打开专用窗口、人工继续以及仅重试报告，继续调用各记录既有且适用的控制能力，使用最新已观察版本；不要为统一外观把手动生成控制调用到自动任务或独立报告身份上。自动报告保留进入对应自动任务运行详情的入口，不将自动化配置搬入三步弹窗。
28. 人工处理仍依据现有真实暂停原因展示指导，继承已修正的普通获取失败与登录/安全验证区分。打开微博、刷新平台页或完成平台操作都不自动恢复；只有用户明确继续才尝试恢复。后台锁、已有结果保存及仅使用已有材料的处理规则不变。
29. 关闭弹窗/抽屉、切页、刷新或返回列表不取消任务、不重新提交、不自动重试。列表及当前打开的状态视图通过原有只读刷新机制恢复进度，终态不被迟到的旧响应回滚为活动状态。刷新、进度播报不抢走选材或阅读焦点。
30. 报告完成后该行提供“查看报告”，不自动跳转。个别条目失败不必导致整份报告失败，详情仍如实显示覆盖不足和失败条目；没有可用来源或没有相关来源沿用明确空结果，不伪造正文。
31. “仅重试报告”仍仅用于既有允许的失败/配置阻塞等情况，复制原报告冻结来源及证据，只重跑报告阶段。新报告在统一列表中单独出现并关联原报告，旧记录和旧正文不覆盖；不得通过修改原手动生成的关联让失败历史消失。重试同样保留幂等和版本冲突语义，不自动导航或强行打开抽屉。
32. 单条失败仍通过重新选材发起新分析尝试；取消/中断的手动生成仍提示重新选择原条目启动新任务并复用成功总结。本次不扩大原地继续或一键重跑的能力，也不把取消行为改成删除历史。

### 报告阅读、兼容与布局

33. “查看报告”进入独立全宽详情，第一屏以报告名称、必要元数据和正文为主。不会在报告表格下方或进度抽屉内重新堆叠完整报告。来源、逐条处理结果、调用信息等辅助内容默认收起或按需访问；必要的覆盖不足/空结果提示不能被隐藏成误导性成功。
34. 保留正文引用定位、来源分页、章节导航、原文入口和内容证据追溯能力；按需查看新生成总结、复用总结、失败/中断条目和已有尝试。历史报告按实际保存内容阅读，媒体已清理时说明缺口，不假装文件仍存在或自动下载。
35. 详情提供明确的“返回报告列表”入口。正常往返和浏览器后退保留列表分页位置；直接访问详情且没有来源位置时返回默认列表。允许页内层级表达，但不恢复二级侧边栏或大段面包屑/重复页头。
36. 为已存在的报告、报告生成、内容及处理尝试链接保留语义兼容。旧生成入口归入列表的生成弹窗；旧报告入口根据身份与状态定位详情或进度抽屉；旧单条任务只在明确历史深链或相关内容详情中呈现，不常驻主页。兼容跳转使用替换语义，保留可解析的目标和分页/引用信息，不产生跳转循环。
37. 新的应用内链接使用规范列表、报告详情及按需状态入口，覆盖自动任务、采集结果和错误恢复来源。非法或已不存在的身份显示可恢复错误并允许回列表，不悄悄替用户打开别的最新报告。
38. 沿用现有组件和视觉体系，弹窗足够容纳内容表格，步骤与底部动作保持可达；需要滚动时限制在合理内容区域。窄屏保持单一生成容器，不使页面整体横向溢出，不让固定操作遮挡内容或跨越左侧导航。
39. 保留表格语义、行选择标签、步骤当前位置、输入标签和错误关联。弹窗/抽屉有正确的焦点约束及关闭恢复位置；步骤切换能把焦点交给新步骤，详情导航进入主要内容，返回恢复有意义的位置。进度以文字表达，不仅依赖颜色。
40. 本次仅调整页面组织及满足统一列表所必需的只读契约。默认无需破坏性数据库迁移；如需查询索引，仅允许兼容性增加并验证历史数据。不得清空数据库、删除历史报告、变更微博登录目录、重新接入其他平台、改写媒体保留或重做自动化执行。

## Testing Decisions

1. 主要测试边界是完整的应用路由/页面交互：通过真实报告页面、表格、弹窗、抽屉与导航模拟用户操作，断言可见内容、可访问角色、地址、选择范围和公开请求结果。沿用现有 React Testing Library、用户事件、内存路由及查询提供者组合，在应用已有的数据请求边界提供确定性响应，不模拟组件内部状态或将每个步骤拆成一套独立测试缝。
2. 测试范围已用“模拟你在应用里点击，不动真实账号和付费模型”的说明向用户非阻塞确认；未收到调整前按本节执行，不因此重开产品访谈。该默认不构成真实账号、外部模型费用或生产数据操作授权。
3. 若统一列表新增或修改后端读取契约，补充现有本地 HTTP 入口层的集成测试，贯穿真实临时 SQLite 数据库及真实仓储，不 mock 拼接/去重核心逻辑。仅替换浏览器、下载器和模型等外部依赖；纯页面移动不要求重建整套采集链路测试平台。
4. 先例包括现有应用路由兼容测试、舆情内容库及选材页面测试、报告生成页面测试、报告选择操作测试、报告阅读与证据测试；后端沿用报告生成、全库选材、专题报告 HTTP 契约及其临时数据库/可控服务夹具。更新旧“提交后跳页”“自动打开最新”“双菜单”的断言，而不是让新实现满足已撤回交互。
5. 覆盖导航只有一个普通“舆情报告”链接，其他导航顺序、默认平台账号页和单层设置不变；主页唯一标题、工具栏同行、只有报告表格，不存在双页签、重复标题、常驻内容库、展开的最新报告或旧单条任务大区。
6. 覆盖手动生成有/无关联报告、自动报告、独立历史报告、原失败及多次重试混合的数据。验证一项工作一行、重试另行、不同来源同数字身份不碰撞，以及关联记录不在同页时仍正确去重。
7. 列表集成场景使用超过两页的混合记录，含相同创建时间、缺名称及缺历史关联；遍历分页核对无遗漏无重复、顺序稳定、生成方式诚实。核对刷新、新增报告与从详情返回对当前页的影响，不用读取全库来掩盖分页契约问题。
8. 覆盖无记录、初次加载、读取错误、刷新错误、部分来源读取失败和详情不存在；错误不能退化成成功空列表或自动选另一条记录。列表/详情初始进入和轮询必须只有读取，无执行副作用。
9. 覆盖空选材也能打开三步弹窗；第一步浏览、跨页选择、当前页全选、全库未分析合并去重、历史失败纳入、已总结条目手动纳入、活动条目禁选、取消任意项和清空。选材后新增内容不改变既有冻结集合。
10. 覆盖两套提示词分别在第二、三步出现且映射正确请求字段；默认值、恢复默认、修改、前后切换、名称预填与更改均生效。校验修改不更新全局设置，不使已有总结被强制重跑。
11. 覆盖最终提交前的无选材、无模型、提示词无效、选材预览未完成/失败/过期、有处理中条目、配置冲突和已有活动任务。入口仍允许准备工作，但不能通过跳步、回车或重复点击绕过最终验证。
12. 覆盖普通关闭重开保留表单、会话选材刷新恢复以及普通提示词不新增持久化；单独覆盖响应不确定的固定请求在重开/刷新后完整恢复。模拟重复点击、迟到响应、失败重试与配置变更，验证同一意图不会重复创建或改用新选材。
13. 覆盖提交成功后清除已提交草稿、关闭弹窗、留在列表、最新页看见新记录；不自动打开抽屉或跳到详情。失败不丢输入，任务完成不打断其他操作。
14. 用可控响应序列覆盖补全、单条总结、报告汇总、人工暂停、失败、空结果、取消、中断和完成。核对行内阶段、已处理与失败计数含义、未知数量和独立重试的报告阶段，不使用时间推进伪造百分比。
15. 覆盖点击行操作才打开抽屉，关闭/切换/刷新保持任务继续且不重提；较老响应不覆盖较新终态。人工处理只有明确点击继续才发出控制请求，原始非验证失败不出现安全验证指导。
16. 覆盖仅重试报告新增可见记录、保留父报告、复用冻结证据且不重跑单条分析；单条失败与取消/中断仍按既有路径处理，不新增自动重试。自动报告使用正确身份并保留自动任务详情链接。
17. 覆盖“查看报告”确实进入下一层地址与全宽详情，而非列表内展开；正文优先、辅助部分默认收起、覆盖缺口可见、来源/引用/章节分页和条目证据仍可查看。正常返回保留页位，直接访问或刷新详情不依赖列表内存状态。
18. 覆盖旧生成、旧报告、旧结果以及携带报告、生成、条目、尝试、来源或章节分页的深链。保留其语义目标，替换式跳转不循环，错误目标有回退，单条任务历史不重新出现在所有用户的主页。
19. 以用户可见行为验证键盘顺序、当前步骤、模态焦点、关闭恢复、详情返回、可访问状态及不依赖颜色的错误/进度。避免把测试绑在 CSS 类、私有 hook、组件拆分或请求次数等无业务意义细节上。
20. 实现后在本机用隔离测试数据复核桌面及窄屏实际布局，重点查看三步弹窗的长表格/长提示词滚动、操作可达、工具栏、状态抽屉和详情阅读；运行相关自动测试及项目既有类型检查、静态检查与构建。不会自动用真实微博账号采集、调用付费模型、清理实际数据或同步到远端环境。

## Out of Scope

- 不实现新的采集器、下载器、平台支持或微博登录/安全验证识别机制；保留现有已修正行为。
- 不新增自动任务编排、自动开始下一份报告、并发生成、隐藏队列或后台无人值守恢复。
- 不重做报告生成执行引擎，不新增强制重分析已有总结、取消后原地恢复或批量重跑功能。
- 不提供独立内容库导航，不恢复“生成报告/报告记录”双页面或双菜单，不在主列表常驻大进度面板。
- 不增加报告列表筛选/搜索、统计仪表盘、列配置、导出、删除、批量操作、协作或权限体系。
- 不新增按报告切换模型、多个模型档案或两步分别使用不同模型；模型仍在设置中统一配置。
- 不增加普通提示词/名称的跨刷新长期草稿、自动保存、历史模板管理或额外的选材/配置步骤。
- 不删除、清空或重算已有报告、内容、失败历史、媒体和登录数据；不修改媒体保留策略。
- 不把本次验收扩展为真实账号采集与真实收费模型的端到端验证；不部署或同步到 Centaurus。

## Further Notes

- 决策来源是本功能讨论记录中第四轮以后的单页方向、第五轮三步弹窗与行内进度，以及第六轮用户确认的列表字段和下一层报告详情。中间曾提出的“独立生成报告页顶部看进度”已撤回，不能进入实现。
- 本规格覆盖旧《报告生成页面重构》中关于双页签/双入口、主页常驻选材、两套提示词上下同屏、固定底部选材栏、提交后跳转和默认自动打开记录的界面决定；也覆盖旧《导航信息架构与页面标题精简》中关于报告父级展开、两个规范页面和提交后进入报告记录的决定。无关导航和已确认的简洁标题规则保持。
- ADR-0008 的采集独立入库、明确选材后提交、复用选中条目已有总结、自动化另行配置的业务原则不变；其中生成界面的旧呈现描述以本规格为准。ADR-0002 的用户显式继续、ADR-0009 的微博唯一平台能力继续适用。此次可逆界面组织调整不另建 ADR，领域术语仍以项目 CONTEXT 为准。
