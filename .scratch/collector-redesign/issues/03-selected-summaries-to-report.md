# 03: 手选已有总结生成报告

**What to build:** 用户在报告生成界面从历史内容中选取已有可用单条总结的条目，一次启动生成报告，并查看本份报告采用的来源。不需要先采集，也不自动加入未选内容。

**Blocked by:** None (can start immediately)

**Status:** resolved

Labels: ready-for-agent

- [x] 提供基于内容库的手动选材与开始操作，来源可以跨采集批次；不能只接收最近一次分析任务的全部条目。
- [x] 启动时保存明确的选材集合和所用配置，报告来源仅来自选中的内容；执行中新入库的条目不自动加入。
- [x] 直接复用选中条目的可用成功总结，不发起平台访问、媒体获取或单条模型调用。
- [x] 未被选中的历史总结不会加入报告；选中但没有可用总结的内容应得到明确提示，本票不隐式补跑旧分析流程。
- [x] 页面显示报告生成进度、结果和来源，可区分被选中与最终被报告采用的条目。
- [x] 同一内容可参与多份报告，各份报告保存独立的来源关系和结果，不能用全局内容字段代替报告状态。
- [x] 重复提交同一启动意图不会产生重复报告工作，查看列表、详情和刷新不产生额外模型调用。
- [x] 相关性判断没有可用来源或没有相关来源时不编造报告，报告自身失败不能显示为完整成功。
- [x] 使用既有成功总结的隔离样本，从用户选材到报告交付完成验收，并证明媒体及单条模型外部调用计数为零。

## 执行边界与验证

本票无需等待新采集器，可以使用已存在的内容和总结独立开始。不改变历史数据，不加入自动化编排；尚未总结内容的自动处理由 04 接续。

常规验收使用本地隔离数据库、固定样本和外部依赖替身，通过用户操作及本机应用接口检查最终状态和副作用；不使用日常运行数据，不访问小红书，不购买采集服务，不修改或启动自动化。实际微博账号验证遵循 14 的限定范围；发布本票不等于已开始实施。

对应父规格验收场景：07、17、18。通用范围限制对全部任务有效。
