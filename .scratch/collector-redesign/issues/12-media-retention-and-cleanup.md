# 12: 媒体期限、容量与安全清理

**What to build:** 项目管理者可以在设置中调整媒体保留期限和容量上限，应用据此安全清理缓存。即使媒体已被报告引用也可清理，但正文、单条总结、报告及来源记录继续可读。

**Blocked by:** 11：原媒体持久保存与复用

**Status:** resolved

Labels: ready-for-agent

- [x] 设置界面可读取、修改并保存明确单位的期限与总容量配置，非法值被拒绝，重启后配置保持有效。
- [x] 默认值、空间核算和清理顺序有记录且能够确定性验证，不把媒体容量设置混同为搜索数量或模型输入预算。
- [x] 到期或达到容量条件时只清理应用拥有的原媒体缓存；已被报告引用不会自动取得永久保留特权。
- [x] 正在使用的文件、非应用所有文件及目录替换指向的外部对象不能被误删，无法安全腾出空间时明确停止新增缓存。
- [x] 清理后保留正文、总结、报告、来源与当时处理记录，不将历史成功获取改写为当时获取失败。
- [x] 详情中明确显示原媒体已清理或不在本地，不能继续宣称用户可回看本地原文件。
- [x] 查看已清理内容不自动重新下载，也不因为缓存到期而使已有成功总结自动失效。
- [x] 配置变化、运行中的读写与清理并发保持一致，取消或异常不会扩大清理目标。
- [x] 使用可控时间、临时目录及容量样本，从设置修改贯穿实际清理和历史查看，验证引用过的媒体、在用文件及越界防护。

## 执行边界与验证

原媒体并非永久证据归档。本票不删除正文或报告，不新增自动重采策略，不以媒体清理授权删除用户原始目录。

常规验收使用本地隔离数据库、固定样本和外部依赖替身，通过用户操作及本机应用接口检查最终状态和副作用；不使用日常运行数据，不访问小红书，不购买采集服务，不修改或启动自动化。实际微博账号验证遵循 14 的限定范围；发布本票不等于已开始实施。

对应父规格验收场景：21、22。通用范围限制对全部任务有效。

## 实施验证

默认 30 天 / 1 GiB，允许 1–3650 天、1–20480 MiB。容量计算包含 ready 和 pending 的预留字节；期限从首次缓存成功时计算，复用与 GET 不续期。先到期/未完成写入，再按创建时间及哈希稳定排序腾出空间；新缓存、保存策略、显式清理和应用存续期间每分钟维护执行。只删除数据库记录且 inode/权限/目录归属仍相符的文件；使用中的共享锁、硬链接、目录替换或未知文件令清理暂缓，无法腾出安全空间就拒绝新增缓存。

10 项期限/容量测试通过（含设置、无效值、重启、报告来源保留、租约保护、过期策略、硬链接/目录替换、容量修改与新增文件时的淘汰顺序）；7 项缓存测试通过，相关后端 34 项回归通过。前端设置和缓存交互及导航/结果共 53 项测试、typecheck 通过。所有删除仅作用于测试建立的临时缓存，日常用户数据没有清理或迁移。
