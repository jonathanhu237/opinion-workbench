# 05: 全库未分析与失败项批量处理

**What to build:** 用户可以一键选取内容库中的未分析条目，并选择是否包含当前失败项，随后自动完成分析到报告。不再逐页勾选，也不依赖这些内容是否在最近一次搜索中出现。

**Blocked by:** 04：未分析正文自动总结并出报告

**Status:** resolved

Labels: ready-for-agent

- [x] 报告界面提供按库中处理状态进行批量选材的操作，并明确显示是否包含失败项及实际选材数量。
- [x] 批量选择由完整内容库查询形成，不局限于当前页面、最近采集批次或本次新增命中。
- [x] 不包含失败时选择符合规则的尚未处理内容；包含失败时同时纳入全库当前仍失败的条目，不要求最近再次搜索命中。
- [x] 曾经失败但后来已成功的内容不再作为当前失败项重试；某份报告失败也不会把已总结内容全部变成单条失败。
- [x] 最近采集没有新增时仍能处理库中积压内容，并在处理后生成报告。

- [x] 启动后冻结实际集合，分页浏览或后续入库不改变正在执行的选材；重复提交不会重复执行。
- [x] 尚未接通平台的候选明确标记原因，不静默丢弃，也不调用旧平台账号；统一能力展示由 13 完善。
- [x] 使用超过一页、跨多个采集批次且混合各类处理状态的样本，验证两种策略的准确集合、任务进度和最终报告来源。

## 执行边界与验证

使用未分析而非新增解释处理资格；新增命中仍只描述发现。本票不增加按过期时间强制重分析全部历史的模式；默认是否包含失败采用明确、可见的配置，不把标签含糊性留给执行层。

常规验收使用本地隔离数据库、固定样本和外部依赖替身，通过用户操作及本机应用接口检查最终状态和副作用；不使用日常运行数据，不访问小红书，不购买采集服务，不修改或启动自动化。实际微博账号验证遵循 14 的限定范围；发布本票不等于已开始实施。

对应父规格验收场景：04、05。通用范围限制对全部任务有效。

## Answer

全库准入与统计共用同一资格查询：未首次处理；可选当前可恢复失败（含材料不足、不支持、中断、取消），排除在处理及后来成功的条目。策略与实际选材分别持久保存，实际集合来自启动事务，不受页面或之后入库影响。空集合明确返回无候选，不创建任务。缺少材料且未接通的路径有明确原因，不访问旧账号。

跨历史批次 32 条混合样本验证两种策略；1,001 条验证无分页/手选上限截断；模糊重放及页面手选/全库规则隔离已覆盖。8 项端到端后端、107 项相关前端回归通过；全库客户端另增 1,001 条与规则错配校验；typecheck 通过。没有真实平台访问。
