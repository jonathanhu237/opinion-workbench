# 11: 原媒体持久保存与复用

**What to build:** 用户完成图片分析后，已经取得的原媒体仍作为受管理的本地缓存保留，并可查看保存状态、在必要处理时复用，不再随着单条分析临时目录一并消失。视频遵循同一存储契约。

**Blocked by:** 07：图片内容进入总结与报告

**Status:** resolved

Labels: ready-for-agent

- [x] 从已接通的图片链路完成选材、获取、分析和报告后，原媒体保存于应用管理的缓存，并与对应内容及获取记录关联。
- [x] 区分原媒体缓存、临时模型输入、媒体地址和总结依据，不能仅凭临时文件存在就声称原媒体被持久保存。
- [x] 再次需要同一份有效媒体时可以复用缓存，且已有可用总结仍优先复用，不因增加缓存能力而重新分析全部历史。
- [x] 结果详情能显示本地原媒体仍存在、未取得或已不可用，读取这些状态不启动下载。
- [x] 缓存文件与记录在异常退出后保持可核查的一致关系，缺失或损坏文件不冒充可复用成功。
- [x] 缓存仅管理应用拥有且经过校验的文件，有明确的安全容量上限，容量不足时不无限占用磁盘。
- [x] 文件持久保存与分析临时文件清理相互隔离，清理临时输入不会删除仍需保留的原媒体。
- [x] 图片端到端验证先行；共同清单契约同样能保存视频文件，用固定视频文件验证存储行为，不以真实视频业务已上线作为本票前置。
- [x] 通过临时媒体目录验证正常保留、缓存复用、丢失或损坏、异常中断及读取无副作用，不接触实际用户媒体。

## 执行边界与验证

管理界面中的期限、容量策略及自动清理由 12 交付；本票先提供有界且可恢复的存储基础和可见保存状态。08 完成的视频链路在共同契约下接入，完整真实视频缓存行为由 14 汇合验收。

常规验收使用本地隔离数据库、固定样本和外部依赖替身，通过用户操作及本机应用接口检查最终状态和副作用；不使用日常运行数据，不访问小红书，不购买采集服务，不修改或启动自动化。实际微博账号验证遵循 14 的限定范围；发布本票不等于已开始实施。

对应父规格验收场景：21、22。通用范围限制对全部任务有效。
