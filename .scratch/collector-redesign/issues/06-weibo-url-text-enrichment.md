# 06: 微博 URL 补全正文并出报告

**What to build:** 用户选中只有 URL 或正文不足的微博后，应用通过经核验的本地组件补全正文，保存补全结果，再自动总结并生成报告。整个过程仍由本项目控制范围、登录态、进度和暂停。

**Blocked by:** 01：采集器替换的前置整理；04：未分析正文自动总结并出报告

**Status:** resolved (real-site compatibility remains explicitly gated by 14)

Labels: ready-for-agent

- [x] 形成明确的组件核验结论，检查请求范围、隐式登录、重试、停止能力、输出完整性、版本与分发义务；不能只凭支持列表或成功退出选型。
- [x] 通过项目拥有的指定内容补全边界接入合格组件，不调用 MediaCrawler 的旧微博补全逻辑；解析结果转换为统一的内容与完整性记录。
- [x] 用户从报告界面选择 URL 后能够看到补全进度，补全正文持久保存并自动进入总结和报告，无需额外点击内部步骤。
- [x] 纯文本、长正文、已删除或不可读内容有可区分的结果；搜索摘要和完整正文不能混同，缺口保留到单条总结及报告来源。
- [x] 只允许处理选中的内容，不递归扩展到账号、合集或其他条目；组件内部请求和重试必须受预算约束。
- [x] 必要时只向经审查组件提供本项目对应平台的登录态，不读取日常浏览器或其他平台信息，凭证不进入普通日志和命令行。
- [x] 补全遇登录或安全验证立即进入待人工处理，保留已有结果，显式继续前不再次请求平台；不能因有搜索预览就静默绕过暂停。
- [x] 在正文路径中保留统一媒体清单及传输能力的接入约定，区分媒体地址与实际文件，使图片、视频任务能够独立接续。
- [x] 选中内容已有可用总结时仍走复用，不因接入新补全组件而自动重新抓取旧成功内容。
- [x] 通过离线组件样本及可控外部返回，从 URL 选材贯穿正文保存、单条总结、报告交付及验证暂停；不以账号实测代替常规回归。

## Answer

采用固定版本 gallery-dl 的单帖解析器，但不给它网络、Cookie、用户配置或缓存权限。项目自己的宿主只允许当前 MID 的详情请求，正文入库后由报告父任务自动总结及汇总。401/403/429 进入持久人工暂停，打开专用窗口不等于继续；只有匹配当前版本的显式 Continue 才重试。候选媒体保留为非 ready 的统一清单，实际下载与模型采用分别由 07、08 验证。真实微博兼容性和分发许可核对仍是 14 的退出门槛。

## 执行边界与验证

既有调研中的下载器只作为核验候选。若没有满足控制边界的组件，应记录具体阻碍，不自动选择需要长期大幅 fork 的方案。图片和视频在 07、08 各自贯穿验证，候选地址不计为已经完成媒体获取。

常规验收使用本地隔离数据库、固定样本和外部依赖替身，通过用户操作及本机应用接口检查最终状态和副作用；不使用日常运行数据，不访问小红书，不购买采集服务，不修改或启动自动化。实际微博账号验证遵循 14 的限定范围；发布本票不等于已开始实施。

对应父规格验收场景：09、12、23。通用范围限制对全部任务有效。

## Comments

### 用户补充：微博登录复用准备

用户新增允许将本机 Chrome 中自己的微博登录态复用到项目专用 Profile，作为本票默认不读取日常浏览器信息规则的严格微博范围例外，不授权读取其他网站登录态、保存密码或整个 Profile。补全组件仍只取得项目对应平台任务所需的信息，不直接接管日常浏览器。当前浏览器工具没有会话导出或导入能力且限制读取会话存储，因此迁移尚未实施；授权不等于已经取得可用登录，也不允许绕过工具限制或安全验证。
