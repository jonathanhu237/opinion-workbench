# 舆情工作台：全面改名与去地域限定

## Problem Statement

操作者希望把当前绑定龙田街道的应用作为个人、本地使用的通用舆情工作台。现有产品、GitHub 仓库、本地目录及内部运行标识仍使用 Longtian 命名，新库规则和默认报告提示词还限定龙田街道；仅改页面名称不能解决这些限制。

操作者需要自行填写采集对象和可选舆情词发现内容，并分别通过总结提示词与报告提示词指导分析，不希望系统从采集记录猜测报告应关注什么，也不需要企业账号、云端部署或多工作空间。此次可以放弃旧资料的导入，但不能把“不迁移”理解成允许删除旧资料。

## Solution

将产品统一命名为“舆情工作台”，GitHub 仓库与本地目录统一为 opinion-workbench，清除当前产品及内部运行契约的旧命名，解除默认规则、提示词及当前使用说明中的龙田限定。

保留现有采集与报告分离的工作方式：采集对象必填，舆情词可选，有词则逐对组合搜索，无词则分别搜索对象。操作者分别填写总结提示词和报告提示词，报告关注对象由其报告提示词决定，不另增关注对象字段或确认流程。

新版从空白状态启动，旧内容、配置和登录态保留在隔离位置但不导入。完成仓库及目录改名、本地开发环境重建和验证后，生成 Windows x64 与 macOS Apple Silicon 的免安装 ZIP，上传改名后仓库的新 Release 草稿，不自动公开。

## User Stories

1. As an 操作者, I want 产品名称显示为“舆情工作台”, so that 应用不再看起来只服务龙田街道。
2. As an 维护者, I want GitHub 仓库名为 opinion-workbench, so that 工程入口与通用产品定位一致。
3. As an 维护者, I want 本地目录名为 opinion-workbench, so that 本地工作环境与仓库命名一致。
4. As an 维护者, I want Git remote 指向改名后的仓库, so that 后续推送与发布使用正确入口。
5. As an 操作者, I want 启动入口与下载包使用新品牌, so that 不需要从旧品牌资产中猜测哪个是新版本。
6. As an 维护者, I want 内部包、模块、环境变量及运行标识也去除旧品牌, so that 改名不是仅覆盖页面文案。
7. As an 维护者, I want 当前使用说明和启动指令同步更新, so that 不会因旧命令或路径无法启动。
8. As an 操作者, I want 在个人电脑本地运行系统, so that 无需部署云服务或管理组织账号。
9. As an 操作者, I want 自行填写地区、组织、品牌或主题等采集对象, so that 使用范围不受原地域限制。
10. As an 操作者, I want 一次填写多个采集对象, so that 可以使用同一规则发现不同对象的内容。
11. As an 操作者, I want 缺少采集对象时被明确阻止发起采集, so that 不会执行无对象的搜索。
12. As an 操作者, I want 可选填写舆情词, so that 可以缩小发现内容的搜索组合。
13. As an 操作者, I want 每个对象分别与每个舆情词组合, so that 多组输入形成预期的搜索词集合。
14. As an 操作者, I want 不填写舆情词时分别搜索各个对象, so that 不被强迫添加额外词语。
15. As an 操作者, I want 舆情词只用于发现内容, so that 没有精确出现搜索词但实际相关的内容不会因此被报告排除。
16. As an 操作者, I want 新系统不自动建立龙田及社区规则, so that 不会误采集旧项目对象。
17. As an 操作者, I want 单独填写总结提示词, so that 能控制单条文字理解的要求。
18. As an 操作者, I want 单独填写报告提示词, so that 能指定报告关注对象及分析要求。
19. As an 操作者, I want 两份提示词分别保存并作用于对应阶段, so that 更改报告要求不会被误当成更改单条总结要求。
20. As an 操作者, I want 默认提示词不绑定龙田或特定政务口径, so that 不同对象可以使用同一应用。
21. As an 操作者, I want 报告关注范围由我填写的提示词决定, so that 系统不会自动采用最后一次采集的对象。
22. As an 操作者, I want 跨批次选材时系统不自动合并对象写进报告指令, so that 采集历史不会覆盖我的报告意图。
23. As an 操作者, I want 不新增独立报告关注对象字段或确认步骤, so that 继续通过现有两份提示词完成配置。
24. As an 操作者, I want 每次执行保留当次提示词快照, so that 后续修改配置不会改变既有执行记录的含义。
25. As an 操作者, I want 继续从舆情内容库明确选材, so that 未选中的历史内容不会悄悄进入报告。
26. As an 操作者, I want 文字证据不足的来源继续标记待人工核查, so that 搜索命中不会被当成已经确认相关或已证实事实。
27. As an 操作者, I want 新版以空白内容库和配置启动, so that 不需要承担旧资料迁移的复杂度。
28. As an 操作者, I want 旧内容、报告、规则、提示词和模型配置不自动导入, so that 新版与旧使用状态明确分离。
29. As an 操作者, I want 重新配置模型并登录平台, so that 新版不隐式复用旧凭据或浏览器资料。
30. As an 操作者, I want 旧资料被保留而非删除, so that 放弃导入不会造成不可恢复的数据损失。
31. As an 操作者, I want 旧历史报告中的真实地名保持原样, so that 项目改名不会篡改业务事实。
32. As an 维护者, I want 移动本地目录前安全停止应用及其专用浏览器, so that 数据和进程不会处于半搬迁状态。
33. As an 维护者, I want 改名后的开发环境重新创建并验证, so that 旧绝对路径不会导致启动失败。
34. As an 操作者, I want 新命名后的服务身份、单实例锁与页面生命周期仍匹配, so that 改名不会造成连接失败、重复服务或残留进程。
35. As an Windows 使用者, I want 下载新品牌的 Windows x64 ZIP 并解压启动, so that 无需自行安装开发工具或构建。
36. As an Mac 使用者, I want 下载新品牌的 Apple Silicon ZIP 并通过启动入口运行, so that 不会误用其他架构的二进制。
37. As an 下载者, I want 包名标明版本、系统与架构并附校验值, so that 能选择正确文件并验证完整性。
38. As an 维护者, I want 双平台最终解压包都通过启动检查, so that 编译成功不会被误认为交付成功。
39. As an 维护者, I want 发行包不含旧业务数据、密钥、登录态或日志, so that 发布过程不会泄漏个人资料。
40. As an 维护者, I want 两个平台成功后生成新 Release 草稿, so that 可以在公开前检查完整资产。
41. As an 维护者, I want 历史标签与发行保持不变, so that 改名不会覆盖已有版本或破坏可追溯性。
42. As an 维护者, I want 得到新仓库、成功运行和草稿的实际链接, so that 能确认交付已完成而非仅写好了工作流。

## Implementation Decisions

### 产品范围与领域契约

- 保持个人、本地单一工作空间与现有五平台边界。业务通用化不等于建设对外通用采集平台，符合 ADR-0001。
- 沿用已有采集对象与舆情词分组模型和组合接口，不重建规则系统。对象必填，舆情词可空，组合顺序和校验以现有契约为基础。
- 现有重复词、组合冲突、长度和数量限制继续有效，不在本次静默改为去重，也不放宽采集预算。
- 舆情词不是报告相关性的字面门槛；实际判断由操作者的提示词和原帖文字决定。
- 保留采集入库、手动报告选材和报告生成的边界，遵循 ADR-0008；不自动把新入库内容加入选材，不新增一键采集分析流程。
- 保持 ADR-0011 与 ADR-0012 的原帖文字理解、待人工核查和媒体退出边界。

### 两阶段提示词与默认值

- 复用现有总结与报告两阶段提示词配置、选择、版本、哈希及执行快照机制；不创建另一套关注对象配置。
- 总结提示词指导单条总结，报告提示词指导报告生成及关注范围。不得从采集批次、选材对象并集或最后一次搜索自动拼接关注范围覆盖操作者意图。
- 去除默认报告提示词及规则初始化中的龙田和社区限定；当前界面示例、自动任务示例与说明使用非特定地域的中性表述。
- 没有用户指定的关注对象时，不伪造对象、不默认套回龙田，也不新增自然语言提示词解析器去强制校验对象字段。
- 保留当前可用总结复用策略；不因本次改名引入全库重算或改变提示词修改后的复用语义。
- 自动任务中已有的两阶段提示词选择和快照继续工作；新版不导入旧任务或快照。

### 全面命名与运行一致性

- 中文显示名为“舆情工作台”，仓库及本地目录为 opinion-workbench。内部按各工具命名限制采用同源的新品牌拼写。
- 修改前后端包和模块、入口、健康身份、环境变量、数据库文件及数据根标识、凭据格式标识、浏览器存储键、浏览器所有权锁、冻结程序与辅助进程、构建及发行校验契约，避免只替换可见文案。
- 当前运行、构建和文档中不保留旧产品身份的兼容别名。本次不承诺旧客户端、旧环境变量、旧凭据格式或旧数据格式兼容。
- 不对 Git 历史、发行历史、保留的旧资料或历史业务事实做全局字符串替换；历史地名不是现行品牌残留。
- 清除旧标识不代表删除全部历史数据库迁移逻辑；保留新库初始化仍需要的结构与迁移链，避免无关数据库架构重写。
- 联动验证本机监听、资源定位、API 健康检查、单实例和关闭退出机制，不因重命名扩大网络暴露或改变生命周期。

### 空白切换与本地目录

- 用户明确选择不迁移旧内容、总结、报告、规则、提示词、模型配置、凭据与平台登录态，新版创建独立空白状态。
- 先确认并停止本应用服务、任务及本应用拥有的专用浏览器，不终止无关浏览器或其他进程。
- 旧资料保持原位或安全隔离备份，不主动删除，不在运行中复制正在写入的数据库。备份不提交或上传，不读取秘密内容以生成规格或日志。
- 本地目录改名时，不能把随仓库移动的旧运行目录当作新版数据源；新环境不从旧环境文件或浏览器存储静默导入配置。
- 重建含旧绝对路径的虚拟环境，检查当前有效启动脚本、文档与可发现的本机引用；仓库外引用无法确认时如实列出，不宣称已全面覆盖。
- 当前任务的空白切换是明确的新产品切换选择，不把以往 ADR 中的资料保留要求改写成删除授权。历史资料仍保留，但不由新版继续加载。

### GitHub 与发行

- 重命名现有仓库而非另建仓库搬运，保留提交、标签和发行历史；更新本地 remote，核实新仓库访问与 Actions 状态。
- 仓库重定向及外部链接的实际行为实施时核查，不仅依赖旧地址可重定向作为完成证据。
- 保留版本标签触发原生 Windows x64 与 macOS arm64 构建的流程，构建脚本、资产匹配、元数据和发布校验成套使用新名字。
- 选择未占用的新版本标签，不移动旧标签、不覆盖已有资产。两平台通过后生成同源提交的新 Release 草稿，不自动公开。
- 继续交付完整目录 ZIP、版本/系统/架构标记及 SHA-256；运行依赖随包提供，采集仍依赖本机 Chrome。
- 验证最终解压副本而非只检查构建目录；测试数据不得压回发行资产。
- 开发和应用验证在本机进行，不使用 Centaurus。GitHub 原生构建及离线检查属于已确认的发行范围，不执行真实采集、平台登录或付费模型调用。

## Testing Decisions

### 测试边界

- 优先最高的现有边界：通过最终 ZIP 的实际启动入口验证空白应用启动、静态页面/API、数据隔离及正常退出。这也是双平台最终交付的主要验收边界。
- 业务语义复用现有规则 API 和报告执行集成测试，通过受控采集与模型边界替身检查实际搜索词和实际提交给模型的两阶段指令；不为本次改名另建测试架构。
- UI 只补充真实交互需要的覆盖：对象必填、舆情词可空、两份提示词独立编辑和新名称展示。避免大量依赖内部模块名的测试替代用户行为验证。
- 自动扫描旧品牌可用作命名审计，但不能替代运行测试；结果须区分现行契约与允许保留的历史事实。

### 业务与集成场景

- 复用已有监控规则组合、规则 API 往返与前端组合测试，覆盖多对象多舆情词笛卡尔积、空舆情词、缺对象拒绝、原有冲突与输入限额。
- 新库规则为空，不出现龙田及社区种子；默认两阶段指令无龙田或特定政务地域限制。
- 复用已有两阶段提示词版本/哈希/快照测试及报告生成集成夹具，验证自定义总结指令与报告指令分别进入正确阶段。
- 用跨对象、跨批次选材场景检查报告指令忠实保留操作者配置，不自动加入采集对象、不使用最后一次采集范围。
- 不通过假响应宣称真实 LLM 对相关性的质量已获验证；受控模型测试验证输入契约及结果处理，而非真实模型效果。
- 保持报告选材、已有总结复用、原帖文字不足与待人工核查的既有回归测试。

### 数据、改名与最终资产

- 使用合成旧资料和独立临时位置测试空白切换：旧资料仍存在且未改变，新版不读取旧库、配置、凭据或浏览器资料；不拿用户真实数据库做可破坏性测试。
- 复用已有应用路径、launcher、Windows 交付契约、便携偏好隔离和发行资产校验测试，验证新标识端到端一致。
- 本地改名后重新安装/创建开发依赖并执行前后端校验，确认入口不依赖旧目录绝对路径。
- 双平台原生构建后验证解压启动，覆盖中文/空格路径、不同工作目录、依赖随包、静态资源、空白数据、配置持久化与页面关闭退出。
- 检查包内没有旧资料、密钥、Cookie、日志或开发环境；下载草稿资产后核验校验值、版本、架构和源提交的一致性。
- 保留单平台失败不发布、资产缺失/混合拒绝及公开发行防覆盖的现有发布校验。
- Finder/Explorer 双击和系统安全提示须单独记录是否实际验证；CI 启动检查不能冒称完成这些人工验收。

上述测试边界根据当前代码和既有测试提出。遵照本次“不访谈、直接生成规格”的要求，不追加确认问题，也不声称用户已逐项确认这些测试细节。

## Out of Scope

- 本轮代码实施、Git 提交推送、仓库/目录实际改名、创建标签或触发发布；需用户后续明确要求实施。
- 旧资料迁移、导入、旧内部标识兼容或旧客户端兼容；自动删除旧资料。
- 改写历史报告、历史提交或旧发行资产以清除真实地名。
- 多租户、多账号权限、多工作空间、云部署、跨设备同步或通用采集平台。
- 自动从采集对象推断报告关注范围、新增独立报告对象字段、额外报告对象确认页。
- 行业模板库、提示词自动优化、自然语言对象强制解析或新的相关性硬编码过滤器。
- 改变总结复用政策、全库重算、扩展平台或恢复图片/视频/音轨理解、媒体缓存。
- 安装器扩展、macOS app、Intel Mac、Windows arm64、签名公证、自动更新或自动公开 Release。
- 真实平台采集、付费模型验收、Centaurus 运行。
