# 多平台媒体分析的模型约束

Status: researched

核查日期：2026-09-06。仅核对当前本地代码及阿里云官方文档，未调用模型 API。以下区分产品目标、应用限制和供应商限制。

后续用户另行授权的实际模型调用已完成，见[五平台原帖URL模型实测](url-model-validation.md)；本文件保留能力约束与讨论依据，不用官方能力声明代替实测结论。

## 已确认的产品目标

Q13–Q15 已确认：常规目标为 10 分钟以内视频、单帖 50 张以内图集的完整分析覆盖；有音轨时应传入原音轨，确认原片天然无音轨时允许仅画面分析并标明。覆盖完整视频输入的时间范围不等于模型逐帧无遗漏识别。

## 官方能力与输入限制

- Qwen3.5-Omni 原生视频可理解画面与音频；`modalities: ["text"]` 约束输出，不会关闭视频输入的音轨。[OpenAI 兼容接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)
- 视频时长上限为 1 小时，公网 URL 视频文件上限为 2 GB；单文件 Base64 编码后须小于 10 MB。图片数量上限分别为 URL 2048 张、Base64 250 张。因此 10 分钟和 50 张是可验证的输入规模，不能据此承诺任意质量或组合都通过。[Qwen-Omni 使用说明](https://help.aliyun.com/zh/model-studio/qwen-omni)
- 10 MB 是单个 data URI 文件的限制；未找到该模型整份混合请求的明确总字节限制，应用仍需设自己的总量上限。[错误码说明](https://help.aliyun.com/zh/model-studio/error-code)
- 模型规格列出输入上限 196,608 token、输出上限 65,536 token、上下文 262,144 token；多张高分辨率图片与视频混合时需要合计预算。[模型规格](https://help.aliyun.com/zh/model-studio/qwen3-5-omni-plus)
- 官方建议使用工作空间专属域名，同时说明现有域名仍可使用。本轮无需单因媒体目标强制修改已有北京 `dashscope.aliyuncs.com/compatible-mode/v1` 配置。[兼容接口与域名说明](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)

## 对本地应用的含义

- 应用当前的 30 秒、24 张、媒体合计 6 MiB、编码后整请求小于 9,000,000 字节均为自身限制；它们分散于清单、下载、探测和模型输入，需统一设计，不能只改一个数字。
- 实测 5 分 14 秒头条视频为 28,908,962 字节，即使模型接受其时长，也不能原样放进单个 Base64 输入。按 10 MB 编码额推算，可承载原文件约 7.5 MB；若硬压入 600 秒视频，总码率约 100 kbps，无法预先保证文字和画面细节可辨认。
- Q17 最初提出本地分析副本及必要时分段。用户随后提出整段视频直读、进一步提出仅给原帖 URL 总结；原建议未获接受，当前应先核实 URL 读取路径，不能因现有 Base64 限制预设分段。
- 50 张图片没有必要仅因数量固定分批；按总载荷、上下文及可读性决定是否分批，保留原顺序和每张图实际参与分析的记录。
- 图片缩放、视频预处理、片段边界及重试上限属于后续具体设计与验证。不能以仅送字幕、转写或封面来代替已确认的视频画面和音轨输入。
- 公网 URL 能避开小型 Base64 限制，但引入受控上传与临时可访问地址是另一条架构路径，未纳入当前默认实施承诺；不把带访问参数的平台媒体地址直接交给模型。

## 用户提出的原帖 URL 直接总结

2026-09-06 补充核查。以下是候选路线的能力边界，不是已选架构，也没有进行付费模型实测。

- **图片/视频文件 URL**：Qwen-Omni 支持通过对应的多模态字段输入模型可访问的媒体地址；图片不必先由应用 OCR 成文字，视频可连同音轨进入模型。这种输入仍需获得作品所对应的完整媒体列表，不能用帖子网页 URL 代替媒体字段。[多模态输入文档](https://help.aliyun.com/zh/model-studio/qwen-omni)
- **原帖网页 URL + 联网搜索**：Qwen3.5-Omni 支持 `enable_search`，仅支持 `agent` 搜索策略。搜索来源或一份流畅总结不能单独证明指定原帖的完整正文、全部图片及视频音轨已进入理解。[联网搜索文档](https://help.aliyun.com/zh/model-studio/web-search)
- **原帖网页 URL + 网页抓取/浏览器工具**：供应商提供独立的网页抓取能力，可访问指定 URL 并提取内容；当前官方支持模型列表不含 Qwen-Omni，不能把它视为当前调用只换输入即可使用的能力。官方页面未承诺社交平台登录内容、完整图集或视频音轨的读取范围；这些仍须针对样本验证，未发现承诺不等于已经证明全部不支持。[网页抓取文档](https://help.aliyun.com/zh/model-studio/web-extractor)

若采用工具辅助的 URL 总结，应用可能省去部分平台提取与下载实现，但内容获取转由工具执行。评估须区分正常返回答案、读取了目标原帖、覆盖了原帖所需内容三件事；对照既有真实素材验证图集后部、视频中后段和仅存在于音轨中的信息，记录工具获取证据，不能仅靠模型自述“已读完”。

当前应用的核查结果：`services/ai_client.py:132–155` 未启用搜索或网页工具，`content_understanding.py:14–18` 还明确禁止调用工具、访问链接和搜索；`ai_analysis.py:307–330` 发送正文及本地文件 Base64，原帖 URL 只用于前面的身份校验，没有作为读取目标发送。现有证据能核实传入了哪些文件，不能据模型响应证明每张图或每秒视频都被正确理解。因此 URL 直接总结是需要改接入并验证的新候选路径，不是当前已实现的功能。

## 费用与时延

北京官方价格按每百万 token 计：文本/图片/视频输入 7 元、音频输入 53 元、纯文本输出 40 元；分段会引入额外请求和汇总开销。[官方价格](https://help.aliyun.com/zh/model-studio/model-pricing)

现有应用每次单条理解最多输出 2048 token、等待 180 秒，输出校验失败至多再请求一次；这是调用约束，不是整条内容的费用封顶。分段/分批方案确认后，还需确定整条内容的总调用和等待预算，记录真实用量。未做有付费 API 的价格或时延实测，不提供单条/整份报告的固定价格承诺。
