## 2026-09-08：抖音资源与认证请求

用户在产品专用 Chrome 中遇到两个问题：抖音页面没有样式；补齐静态资源后，手机确认扫码登录，电脑仍停在确认页。

- 现有资源白名单遗漏 `douyinstatic.com` 的 CSS/JS 及字体、登录组件资源。静态资源已按页面实际引用补齐；直接读取页面引用的 CSS 返回 200 和 `text/css`。
- 在产品拦截器中加入按主机、资源类型和原因去重的有界诊断，不记录路径、查询参数、请求头、Cookie、请求体或完整异常信息。
- 实际登录检查记录了 `auth.zijieapi.com` 的 Script 请求、`security.zijieapi.com` 和 `mssdk.bytedance.com` 的 XHR 请求被拒绝；验证 iframe 的 Document 请求也被误拒绝。
- 补齐认证及验证子资源，并仅允许指定静态主机的 `/obj/rc-verifycenter/` 文档作为子框架加载。顶层导航仍限于平台域名，请求预算和冻结控制保留。
- 修复后重新打开产品的抖音检查，上述资源未再出现在拦截记录中；接口进入 `action_required / complete_login`。真实登录成功仍等待用户重新扫码确认后验证，不将回归通过视为登录完成。
- 41 项浏览器生命周期及资源边界测试通过，Ruff 和差异空白检查通过。

记录中的 WebSocket、视频、监测类请求仍按现有策略处理。尚无证据证明 WebSocket 是此次登录阻塞的原因，未为此全面放开网络。五平台采集、内容入库及报告的完整实机验证仍未完成。
