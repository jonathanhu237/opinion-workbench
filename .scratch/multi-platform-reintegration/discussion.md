# 四个平台重新接入讨论

Status: discussion-complete

以下按阶段保留讨论记录。讨论收口后用户另行授权了独立工具试验，结果见文末 Comments 及 [实测记录](real-validation.md)，未开展应用实施。

2026-09-06 后续范围变更：用户在 [接入设计讨论](integration-design.md) 的 Q19–Q22 中改为原帖文字理解，并确认报告中的人工核查提示、全部文字不足仍交付报告，以及旧底座总结不复用。最终有效要求见 [spec.md](spec.md) 与 [ADR-0011](../../docs/adr/0011-text-only-analysis-scope.md)；本文件下文的多媒体目标、旧总结复用及“全部没有可用来源不能形成正常报告”须按该变更理解，文字不足与采集/模型运行失败不能混为一谈。

## 目标与边界

- 用户已完成微博全链路，希望重新加入此前删掉的其余四个平台，沿用取得 URL 后由下载器补全信息的方式。
- 本轮使用 grill-with-docs，仅讨论并更新文档；讨论完成后明确告知用户，并等待明确的实施请求。
- 当前应用实现仍是微博单平台；CONTEXT.md 与 ADR-0010 记录本轮已确认的目标领域范围，不代表四个平台已可运行。
- 本项目保持本地运行，不使用 Centaurus。

## 已核实的现状

- 四个平台为抖音 `dy`、快手 `ks`、小红书 `xhs`、今日头条 `toutiao`，不是 B 站。ADR-0009 与移除前的平台目录相符；旧规格中出现 B 站是历史文字，不作为本次范围依据。
- ADR-0009 要求未来按新能力重新接入；v26 迁移已清理非微博数据并收紧数据库约束，因此不能只恢复界面选项。
- 当前微博通过浏览器发现 URL、独立入库；用户选材生成报告时自动进行必要补全、单条总结及报告汇总。
- 当前补全组件为锁定版本的 gallery-dl，其请求桥接和数据投影有微博专属约束，不能当作已支持任意平台的 URL 下载入口。
- 当前没有现成的手动粘贴 URL 入库产品入口。
- 工作区原先已有 CONTEXT.md 对报告记录状态的未提交修改，本轮保留该修改。

## 第一轮已确认（Q1–Q4）

1. Q1：四个平台全部接入关键词采集、平台登录、内容库、报告生成和自动任务。内部逐个平台实现和验收，最终交付五个平台完整流程。
2. Q2：从平台内关键词搜索发现 URL；本轮不增加手动粘贴链接、账号主页或榜单采集入口。
3. Q3：以原帖或作品为边界，补齐正文、作者、发布时间及图片/视频，沿用现有互动数据字段；不扩展评论、回复和关联推荐。今日头条包含文章全文，不只标题或摘要。缺失媒体沿用已有缺口标注。
4. Q4：某个平台出现登录或验证码等人工障碍时，同一批次整体暂停；用户处理后显式继续，沿用 ADR-0002。

## 第二轮已确认（Q5–Q8）

- Q5：用户调整默认值为新建时全选五个平台。手动采集及自动任务允许多选；既有自动任务仍保留原先已保存的平台范围，用户未要求迁移时自动扩大旧任务。
- Q6：各平台独立计算每词上限。用户举例：词 A 在微博搜索 20 条，在快手也搜索 20 条；五平台全选时同一个词最多取得 100 条平台内容，不足时保留实际结果。
- Q7：用户确认普通失败继续其他平台。按该问题提出的行为，自动任务使用可用来源生成报告，并明确记录、显示采集缺口；全部没有可用来源时不能形成正常报告。登录/验证码等仍整批暂停。
- Q8：用户对推荐方案无异议。代表性视频的画面及音轨必须实际进入分析才算视频平台验收通过，允许调整有界预算；超限个例仍可保留部分结果，不能仅靠文字成功宣称完整接入。
- 补充事实已告知用户：视频不仅有 6 MiB 限制，还有 30 秒时长、格式、模型输入与请求体约束；报告目前也没有平台搜索缺口快照。这两项建议都是实际新增行为，不是已有能力描述。

## 沿用的既有规则

- 采集先去重入库，手动选材生成报告时再进行必要补全；自动任务按现有编排衔接采集与报告。
- 同平台同一内容继续按平台内容身份去重，访问 URL 的变体不创建重复内容；跨平台转载保留各自来源记录，不新增内容相似度合并功能。
- 继续复用可用正文、媒体与成功总结，保留失败尝试和既有报告；媒体遵循现有保留策略。
- 本地组件仅使用本项目对应平台的必要登录态，保留请求范围、预算、取消和人工恢复控制；不恢复 MediaCrawler。

## 第三轮已确认（Q9–Q12）与调研顺序纠正

- 用户对 Q9–Q12 回复“我没意见”，并指出应先核查是否已有补全工具，不能先把工具能力不足当成自写适配的前提。
- Q9：优先使用现成组件，允许必要的平台专属提取逻辑及正文提取器与媒体下载器组合；仍限定已发现的单条 URL。该接受不等于已证明必须自写，应先调研和验证现成工具。
- Q10：今日头条范围为文章全文、微头条原帖及配图、独立视频；视频须进入画面和音轨分析。
- Q11：互动数量缺失时允许内容参与分析，缺失统计为未知，不写成零，不因统计缺失阻断报告。
- Q12：平台有可用最新排序时使用最新；没有时按平台实际提供的顺序采集并记录排序方式，不把综合排序标为最新。
- 下一步先深入核查候选的单 URL 调用链、字段、媒体能力、维护状态及接入方式，形成具体工具比较，不继续把可查事实交给用户决定。当前只更新文档和开展工具研究，没有实施授权。

## 设计树

- 产品范围：已确认五平台完整流程。
  - 平台选择和旧任务默认范围：已确认新建全选，可调整；既有任务保留原范围。
  - 每词采集上限在多平台下的计数范围：已确认每个平台独立计算。
  - 自动任务面对部分平台普通失败时的报告行为：已确认继续其他平台并说明采集缺口。
- 发现方式：已确认平台关键词搜索。
  - 平台实际搜索能力、URL 身份及必要访问参数：公开资料调查见 research.md，实际页面验证归入实施验收。
  - 无可用最新排序时的产品行为：已确认使用平台实际顺序并如实记录。
- 内容补全：已确认原帖正文及图片视频，头条包含全文。
  - 各平台现成组件的真实能力：已完成扩展官方资料及源码核查，见 tool-shortlist.md 与各专项记录；有明确验证候选，真实样本和最终版本选择属于后续技术验证。
  - 现有媒体预算能否满足视频平台完整理解：已确认允许调整预算，验收要求实际视频与音轨输入。
  - 组件存在能力缺口时的适配边界：已确认优先现成组件，允许必要适配与组件组合；先完成具体工具研究，不能预设必须自写。
  - 今日头条具体作品类型：已确认文章、微头条及独立视频。
  - 互动字段缺失时的处理：已确认标为未知，允许参与分析。
- 人工恢复：已确认整批暂停、用户显式继续。
- 文档与实施：讨论收口后整理已确认边界，实施另候用户明确指令。

## 讨论收口

- Q1–Q12 的产品决定均已确认，需求讨论完成；新建默认全选五个平台，各平台每词独立计数，普通失败继续其他平台，人工障碍整批暂停并显式继续。
- 四平台最终覆盖关键词发现、登录、入库、选材补全、报告与自动任务；现有微博链路、数据、配置和登录状态保留。
- 工具调查已形成可审阅的[候选与验证顺序](tool-shortlist.md)：小红书优先验证 XHS-Downloader，快手 KS-Downloader，抖音 F2；头条按文章 NewsCrawler/Trafilatura、微头条 ToutiaoCrawler 技术候选、独立视频 yt-dlp 分别验证。替代候选、许可未明确项和具体调用缺口详见专项记录。
- 此前“缺工具就可能自写”的讨论不作为实施前提：先对真实样本验证现成组件，再按已确认 Q9 判断是否需要最小适配。没有任何候选在本轮经过登录、真实内容获取或媒体验证。
- 后续实现者负责核实版本、真实作品覆盖、搜索页面行为及有界视频处理方案；不再要求用户代查工具能力，也不把未知的技术事实包装成已经完成的接入。
- 本轮仅更新领域术语、ADR、讨论与研究文档，没有修改应用代码或数据库，没有启动应用服务或使用 Centaurus。等待用户明确请求实施。

## Comments

- 2026-09-06：用户在收到候选清单后明确回复“行，那你先试试看”，授权先做真实 URL 工具试验。本轮在独立本地环境执行，未改动应用代码、数据库、依赖或既有登录状态。
- 试验已完成，详见 [实测结果](real-validation.md)：50 张图片、3 条含音轨视频完成文件检查；小红书可复用，头条可按内容类型组合，抖音 F2 返回 403 而 parse-video-py 取得媒体，快手分享图集可取但桌面视频与部分失败后的记录行为有缺口。
- 上述为工具级证据；关键词采集、登录人工恢复、入库、报告、自动任务和视频 AI 输入的正式产品验收尚未执行。
