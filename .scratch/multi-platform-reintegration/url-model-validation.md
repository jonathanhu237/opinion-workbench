# 五平台原帖 URL 直接交给模型：实测

Status: probe-complete

日期：2026-09-06。用户明确要求实际尝试五个平台的原帖 URL，并在当前模型不行时查找其他模型。本轮是独立模型探针，没有实施平台接入或替换现有应用流程。

**后续更新：用户更换密钥后，Qwen3.8-Max 已成功完成7次实际调用。最新结果见[新密钥复测](qwen38-url-validation.md)。下文为旧密钥首轮记录；不再将Qwen3.8-Max标为当前不可调用。**

## 首轮结论

**仅给原帖 URL，可以总结部分原帖文字，但本轮没有验证出能统一读取五个平台完整图文、视频画面和音轨的方案。**

- 当前 `qwen3.5-omni-plus` 开启联网搜索后，五平台首轮均未取得可总结的原帖内容；小红书改用完整访问链接后仍未取得。
- 换成 `qwen3.5-plus` 的 Responses API，并配置 `web_search` 和 `web_extractor`，取得了微博与头条文章正文；小红书视频帖的完整访问链接取得标题和短文案。获取到的文字与本地既有样本可对应。
- 小红书图集、抖音视频、快手分享图集未取得可总结内容；头条视频只取得标题。没有完整图集、视频画面或音轨读取通过的证据。
- 尝试 `qwen3.8-max` 时，当前凭证通过该 Responses 接口收到 `Model access denied.`；实际错误码是 `server_error`。能够确认调用被拒绝，但未核实是账号/业务空间授权、接口支持还是服务侧问题，不能记为模型读取平台失败。

这些是所列具体样本、当时链接和调用配置的结果，不能推广成平台所有原帖永久可用或不可用。

## 输入和试验方式

每次是独立请求，输入仅包含一条原帖 URL 和相同的读取、总结、覆盖说明要求。没有给被测模型标题、正文、已下载图片、视频、Cookie、浏览器登录状态、本轮对话历史或本地对照答案。要求模型区分原帖和搜索摘要，未读到就说明，不能根据常识补写。原始请求体逐次保存，可检查实际输入。

使用应用已配置的北京 DashScope 服务及原凭证，仅在内存读取该配置指向的凭证文件；没有修改应用设置、秘密文件、服务、数据库或模型默认值。

| 模型路线 | 实际请求 | 返回结果与用量 |
| --- | --- | --- |
| Qwen3.5-Omni-Plus，Chat Completions，`enable_search=true`、`agent` | 6 次：五平台各一条，小红书完整链接补测一条 | 均返回明确无法读取的回答；共报告 14,453 输入、1,923 输出 token；单次约 6.3–11.7 秒 |
| Qwen3.5-Plus，Responses，网页抓取与搜索工具 | 9 次：五平台各一条，加头条视频、小红书视频，以及两条小红书完整链接补测 | 共报告 26,564 输入、6,482 输出 token；10 次网页抓取、2 次搜索；单次约 11.2–29.1 秒。返回回答不等于素材读取成功 |
| Qwen3.8-Max，Responses，网页抓取与搜索工具 | 五条样本请求均返回拒绝访问 | HTTP 200 的 SSE 内为 `response.failed`，错误为 `server_error` / `Model access denied.`；具体根因未确认。未返回 token 用量，不将缺失用量认定为零费用 |

15 次完成的模型调用合计报告 49,422 token。没有查询账单，不声称精确金额或免费。探针每请求最多等待180秒，响应上限2 MB，回复上限2200/3000 token（3.8候选为4000）；无应用层自动重试。工具内部的获取与重试由供应商执行，本地请求限制不等于能控制其全部内部调用；本轮均在时限内结束。

## 实际总结能达到什么程度

以下为本轮返回结果的概述，不是再由模型读取一次：

- 微博：总结到了居住用地改作重卡停车及充电场、凌晨噪声73分贝、居民消防担忧，以及街道对土地经营和噪声管理的回应。
- 头条文章：总结到了龙田街道的街区治理、闲地改花园、便民摊位和新增停车位，含多个原文特有数字。
- 小红书视频帖：能复述野牛伤人事件的标题和安全距离提醒，但这些来自页面文字，没有证明看过69秒视频。

图片与视频验证对照由另一只读核查任务预先根据既有素材建立，没有交给被测模型。例如，小红书图集首末张有不同大字，快手图集含搬运演练和培训，头条视频中后段呈现不同无人机图案。本轮没有返回足以通过这些检查的媒体观察。

另外，头条文章的网页工具自行生成的附加摘要把配图描述为交通路口，但本地已核对配图是河道、公园及住宅楼；最终回答并未采纳这个画面描述。网页工具返回的文字也需要核对，不能把它的描述直接当作图片已经正确进入理解的证据。视频音轨本轮没有人工听取对照，不编造音轨内容或转写准确率。

## 其他模型：官方核查，尚未实测

| 候选 | 可用能力与限制 | 当前结论 |
| --- | --- | --- |
| [Gemini URL Context](https://ai.google.dev/gemini-api/docs/url-context) | 支持公开网页、图片、PDF；要求页面无需登录；明确只取所提供URL，不递归取嵌套链接 | 是网页直读候选，不能由此认定会把帖子中的全部图集、视频和声音一并取得 |
| [Gemini 视频理解](https://ai.google.dev/gemini-api/docs/video-understanding) | 有视频输入及YouTube URL专门支持；[外部文件输入](https://ai.google.dev/gemini-api/docs/file-input-methods)可以提供公开媒体文件URL | 五个平台的帖子网页不等同于视频文件直链或YouTube URL，仍需针对平台验证 |
| [Claude web fetch](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool) | 可取网页文本、HTML、PDF；官方明确不支持JavaScript动态渲染 | 适合公开文字页，不能直接作为完整图集和视频音轨获取方案 |
| [Claude browser use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool) | 模型可操作动态网页，但浏览器和动作由应用执行，应用返回文字、截图和状态 | 可以研究浏览器代理路线；不是更换模型名称即可省去本地浏览器集成 |

本轮实际调用的凭证来自现有DashScope配置；Gemini和Claude只查了官方能力，没有调用其API，也没有搜索其他账号的凭证。不能把这两者写成已试成功或已试失败。

Qwen调用依据：[Omni多模态及联网搜索](https://help.aliyun.com/zh/model-studio/qwen-omni)、[网页抓取](https://help.aliyun.com/zh/model-studio/web-extractor)、[Responses接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)。实际试验中网页工具返回了可核对的提取文本与调用记录；Omni流式响应未暴露等价抓取记录，其关于搜索来源和失败原因的自述不当成已证实的技术根因。

用户追问拒绝访问后重新核查：官方确认 `qwen3.8-max` 是有效[模型ID](https://help.aliyun.com/zh/model-studio/qwen3-8-max)。[首次调用说明](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen)把 `Model.AccessDenied` 的一种情况归为子业务空间未获模型授权，但本次实际收到的是通用 `server_error`，不能直接套用为已确认根因；也未检查账号控制台或调整授权。此前将其简写为“账号权限拒绝”不够准确，现以原始响应和这一限定为准。

## 对设计讨论的影响

“让模型服务负责读取原帖”已经有文字场景的实际价值，可以继续讨论用它替换哪些文字获取路径。当前没有证据支持删除五个平台全部补全能力，尤其不能取消已确认的图片、视频画面与音轨覆盖要求。此处记录试验结果，不代表用户已经接受新的混合架构、分段方案或补缺入口。

探针源码：[url_only_probe.py](probes/url_only_probe.py)。完整请求、流式事件、模型回答、用量汇总及独立对照保存在 `runtime/tool-validation/url-only/`，由Git忽略；凭证未写入这些文件。应用配置修订号仍为1，本轮没有提交Git变更。
