应用当前设置由用户改为 `qwen3.8-max`，修订号3，仍使用北京 DashScope 接口。先以头条文章进行一次调用，确认返回 `response.completed`、`model=qwen3.8-max` 后，再测试其余四个平台及两条补充视频帖。没有改回用户的配置，也没有调用应用的报告生成流程。

## 对“能总结”的判断

- **有原帖文字依据**：微博、头条文章、快手短文案、小红书视频帖短文案，可以形成对应范围的文字总结。
- **只有搜索摘要依据**：抖音返回了相关信息，但与直接取得原帖存在区别；本轮不把该条归为原帖读取成功。
- **只有标题或完全未取得**：头条视频只有标题，小红书图集未取得原帖内容；不能生成媒体内容总结。
- **完整媒体读取未通过**：没有确认任何完整图集、视频画面和原音轨已进入理解。快手的错误内容类型说明，“未从页面提取到”仍可能被模型误写成“原帖没有”。

这些结论基于本次具体样本及调用，不推断平台所有内容永久可用或不可用。相比上一轮，快手本次取得文案、抖音本次搜索取得摘要，但模型、密钥与调用时间均有变化，不能把差异全部归因为模型升级。

## 调用与用量证据

使用与前轮相同的 [URL探针](probes/url_only_probe.py)，Responses API 提供 `web_search` 和 `web_extractor`，思考强度为 `low`，每次最多4000输出token、180秒、2 MB流式响应，无应用层自动重试；仅一次成功后才启动后续样本，进程最多2请求并发。响应体内的实际模型字段均为 `qwen3.8-max`，错误均为空。

- 完成7次模型请求，单次约22.0–45.8秒。
- 服务报告59,077输入token、8,042输出token，合计67,119token；包含缓存输入，未核对账单，不能当成精确费用。
- 服务报告18次网页抓取、5次搜索。这些是供应商内部工具调用，不能将7次顶层请求当作只抓取了7次网页。
- 原始请求、流式工具记录、最终回答及汇总存于 `runtime/tool-validation/url-only/key-updated-web-*/` 和 `key-updated-summary.json`，由Git忽略；没有写入API密钥。
